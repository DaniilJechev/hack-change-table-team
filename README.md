# AI-buddy

Помощник стажёра для Hack&Change 2026. Цель — сократить рутинные затраты времени
наставника. Основной интерфейс — Telegram и обычный диалог; дополнительный канал —
Windows-клиент AvitoCode. Данные демонстрации синтетические и не являются регламентами Авито.

| Сценарий | Что делает |
|---|---|
| H0 — бриф | Личные изменения GitHub, Jira и Calendar, приоритеты и ссылки |
| H1 — доступы | Проверяет пять инструментов; по кнопке подаёт заявку в имитацию сервиса доступов |
| H2 — команда | Отвечает по карточке, FAQ и Jira; помогает передать вопрос человеку |
| H3 — playbook | Ищет в фиксированном снимке AvitoTech Playbook и указывает источники |
| H4 — экватор | Проверяет текст PDF/PPTX, структуру и факты Jira, сравнивает версии; файл не редактирует |

Текущее описание обновлено 15.11.2026 для ветки `improved_structure`.
Реализованная возможность, проверка на фикстурах и проверка с настоящим сервисом —
разные статусы: [текущий статус и оставшиеся задачи](docs/3_ROADMAP.md).

Ссылки появятся здесь после проверки файлов и доступности для жюри. Сценарии описывают
план выступления и записи, а не проведённый пользовательский пилот.

Путь стажёра: в первые дни разобраться в команде (H2), получить доступы под задачу (H1),
каждый день видеть изменения (H0), находить практики в Playbook (H3), подготовиться
к экватору (H4). Это выбранные сценарии, не полное покрытие чек-листа новичка Авито.
Гипотеза пользы для команды — меньше рутинных обращений к наставнику. Цель пилота:
снижение рутинных минут наставника на стажёра в неделю не менее чем на 25% при
сохранении качества; достигнутую экономию пока не заявляем.

## Маршрут эксперта до интерфейса

**Основной интерфейс — Telegram.** Для самостоятельного запуска нужен собственный
токен тестового бота. Корпоративные аккаунты GitHub/Jira/Miro/Google и LLM-ключ
в базовом демо не нужны. Соединение с Telegram требуется. Загрузка Docker-образов
и зависимостей при первой сборке также требует сети.

1. Скопируйте `.env.example` в `.env`, только если своего `.env` ещё нет (команда ниже).
2. Установите `DEMO_MODE=true`, `LLM_IN_DEMO=false`, `LLM_PROVIDER=fake`,
   `RAG_SEARCH_MODE=bm25`; внесите собственный `TELEGRAM_BOT_TOKEN` в `.env`.
3. Выполните команды раздела «Запуск и применение настроек».
4. Откройте личный чат с ботом, которому принадлежит указанный токен, и отправьте `/demo`.
   Персональное приглашение и seed backend для этого режима не нужны.
5. Выполните таблицу «Проверка экспертом». Начальное состояние возвращает `/demo reset`.

Не запускайте второй polling-процесс с тем же токеном. Уже запущенный сервис не нужно
останавливать ради чтения инструкции. Для независимой копии используйте другой токен.

**Вариант без внешних аккаунтов — Windows-клиент в режиме разработки.** Требуются
Windows 10/11 x64, Docker Compose, Node.js 24 и npm. В `.env` задайте:

```dotenv
DEMO_MODE=true
LLM_IN_DEMO=false
LLM_PROVIDER=fake
RAG_SEARCH_MODE=bm25
TELEGRAM_BOT_TOKEN=
LLM_API_KEY=
CLIENT_API_ENABLED=true
```

Это настройки отдельного локального демо; не очищайте токены в используемом рабочем
`.env`. После запуска стека откройте второй терминал в корне репозитория:

```powershell
cd desktop
npm ci
npx install-electron --no
npm run dev
```

Electron 45 загружает исполняемый файл отдельно. Команда `npx install-electron --no`
устанавливает бинарник версии из lock-файла до запуска electron-vite; без неё на чистой
установке возможна ошибка `Electron uninstall`. Для загрузки нужен доступ к GitHub Releases.
Если загрузка зависла, не считайте завершение `npm ci` подтверждением установки Electron.
Описание механизма: [Electron installation](https://www.electronjs.org/docs/latest/tutorial/installation#binary-download-step).

После запуска клиента:

1. Откройте окно приложения из трея.
2. Зайдите в настройки и укажите корневой адрес агента: `http://127.0.0.1:8081`.
   Если в `.env` задан другой `AGENT_PORT`, используйте его. Например, при проверке
   отдельного чистого стека использовался `http://127.0.0.1:18081`.
3. Примените адрес в настройках, затем нажмите «Попробовать синтетическое демо».
4. После входа выполните таблицу «Проверка экспертом» ниже.

При HTTP 404 сначала проверьте адрес: он должен вести на агент этого стека, без
суффикса `/client/v1`, а не на backend или другой запущенный экземпляр.
Loopback HTTP разрешён только
development-клиенту; установленная production-версия требует HTTPS. Вход Telegram/SSO
для этого демо не нужен. История демо-сессии сбрасывается при перезапуске агента.
Проверка доставки H4 в Telegram относится к основному маршруту, не к запуску без Telegram.
Подробнее: [Windows-клиент](desktop/README.md).

## Настройка .env — до запуска

Нужны Docker Engine/Desktop с Compose v2. Для вспомогательных скриптов — Python 3.12;
Make необязателен. Go на хосте нужен для локальных Go-тестов, но не для сборки контейнеров.

Версии: Go 1.24 (`backend/go.mod`), Python 3.12, PostgreSQL 16 + pgvector, Redis 7,
Grafana 12.0.2; desktop — Node.js 24. Python-зависимости закреплены в `agent/uv.lock`,
Go — в `backend/go.mod` / `go.sum`, desktop — в `desktop/package-lock.json`.
Используйте `uv --frozen` и `npm ci`, чтобы воспроизвести выбранные зависимости.

Из корня проекта создайте `.env` из [.env.example](.env.example), если файла ещё нет.
Существующий `.env` не перезаписывайте:

```powershell
if (-not (Test-Path -LiteralPath .env)) { Copy-Item -LiteralPath .env.example -Destination .env }
```

В Linux/macOS: `test -f .env || cp .env.example .env`.
Compose автоматически читает корневой `.env`; переменные shell имеют приоритет.
Секреты хранятся только локально и не попадают в Git.

| Режим | Минимальные значения в .env |
|---|---|
| Фикстуры без аккаунтов и LLM | `DEMO_MODE=true`, `LLM_IN_DEMO=false`, `LLM_PROVIDER=fake`; токен Telegram и LLM-ключ пустые |
| Telegram с фикстурами и настоящей LLM | `DEMO_MODE=true`, `LLM_IN_DEMO=true`, `TELEGRAM_BOT_TOKEN`, `LLM_PROVIDER=openrouter`, `LLM_MODEL`, `LLM_API_KEY` |
| Живые данные | `DEMO_MODE=false`, настоящая LLM, профиль в backend и read-only учётные данные нужных источников; Telegram-токен для Telegram-канала |

Демо с LLM расходует API-бюджет. Для Telegram на фикстурах без LLM достаточно
добавить токен в первый режим. Без Telegram интерфейс desktop можно включить
через `CLIENT_API_ENABLED=true`; вход и ограничения описаны в [desktop/README.md](desktop/README.md).

| Переменные | Назначение |
|---|---|
| `LLM_PROVIDER`, `LLM_MODEL`, `LLM_API_KEY` | Провайдер и модель только из окружения |
| `LLM_BASE_URL` | Адрес API при `LLM_PROVIDER=compatible` |
| `AGENT_ENGINE=graph`, `AGENT_MODE=agent` | LangGraph и агент с инструментами; без настоящей LLM сохраняется Router |
| `BUDDY_SERVICE_KEY` | Общий ключ backend/agent; задайте собственный для использования вне локального демо |
| `POSTGRES_PASSWORD`, `GRAFANA_*_PASSWORD` | Пароли; локальные defaults Compose предназначены для демонстрации |
| `RAG_SEARCH_MODE=bm25` | Поиск без загрузки модели; `vector`/`rrf` требуют дополнительных зависимостей и индекса |
| `BRIEF_TIME`, `BRIEF_TIMEZONE`, `REDIRECT_BASE_URL` | Расписание брифа и доступный пользователю адрес учёта кликов |
| `MEMORY_*`, `REDIS_URL` | Память диалога; в демо она остаётся в процессе |
| `H4_*`, `CLIENT_API_ENABLED` | История/пороги презентаций и дополнительный клиентский API |

Полный пример с комментариями: [.env.example](.env.example). При запуске Python вне Compose
задайте согласованную пару `BACKEND_URL` и `BUDDY_SERVICE_KEY`; Compose передаёт её сам.
Изменение пароля PostgreSQL в `.env` не меняет пароль уже созданной БД в существующем томе.

## Запуск и применение настроек

Базовый стек — пять сервисов: PostgreSQL + pgvector, Redis, backend, agent, Grafana.

```powershell
docker compose up --build -d --wait --wait-timeout 180
python infra/setup_grafana.py
docker compose ps
```

Для чтения PPTX добавьте шестой сервис, он не требует корпоративного аккаунта:

```powershell
docker compose -f docker-compose.yml -f docker-compose.powerpoint.yml up --build -d --wait --wait-timeout 180
```

PDF читается без PowerPoint MCP. Live Jira и Calendar подключаются отдельно:
[mcp/README.md](mcp/README.md). В демо корпоративные MCP не требуются.

После изменения `.env` пересоздайте соответствующие контейнеры через `docker compose up -d`;
обычный `restart` не применяет новую конфигурацию. Используйте те же `-f`, что при запуске.
После изменения кода добавьте `--build`. Не запускайте второй polling-процесс с тем же токеном.

С Make: `make up`, `make pptx-up`, `make demo`. Последний использует `.env.example`,
но унаследованные переменные shell могут переопределить значения.
`docker compose down` / `make down` останавливает стек и сохраняет тома. Не используйте
`down -v` для обычной остановки: там пользовательские данные и история.

Порты по умолчанию доступны только локально:
[backend health](http://127.0.0.1:8080/health),
[backend ready](http://127.0.0.1:8080/ready),
[agent health](http://127.0.0.1:8081/health), [Grafana](http://127.0.0.1:3000).
Они переопределяются `BACKEND_PORT`, `AGENT_PORT`, `GRAFANA_PORT`.
Grafana Viewer создаётся скриптом настройки; локальный login — `viewer`, пароль
задаёт `GRAFANA_VIEWER_PASSWORD` (демонстрационный default указан в Compose).

## Проверка бота

### Проверка экспертом: от запроса до результата

Ориентир — 10 минут после сборки и открытия интерфейса. Демо-профиль: Даниил,
Backend-стажёр учебной команды заказов; наставник Анна, тимлид Олег. Пароли этих
синтетических участников не нужны: `/demo` создаёт изолированный учебный контекст.

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | `/demo`, затем `/demo reset` | Первый шаг синтетического сценария |
| 2 | `/brief` | Изменения GitHub/Jira/Calendar, главное действие и ссылки |
| 3 | «Какие доступы нужны для ORD-118?» | Статусы инструментов задачи, недостающий Miro, кнопка заявки |
| 4 | «Запросить доступ: …» для Miro | Ответ имитации: заявка на согласовании |
| 5 | Повторить вопрос о доступах ORD-118 | Сохранённый результат заявки; новый запрос не требуется |
| 6 | `/demo next`, повторить тот же вопрос | Следующий набор фикстур: результат согласования granted; реальные ACL не изменяются |
| 7 | «Упал staging, кому писать?» | Маршрут своей команды с источником |
| 8 | «Что такое Zero Bug Policy?» | Фрагменты публичного Playbook и ссылки; без LLM — извлечения, не свободная генерация |
| 9 | Отправить `fixtures/equator/bad.pdf`, затем `good.pdf` | Замечания, сравнение версий и результат обязательных проверок |
| 10 | В Telegram: «Отправить наставнику» после успешной проверки | Файл и отчёт в том же демо-чате; не проверка реальной доставки наставнику |
| 11 | `/interns` от стажёра | Отказ: сводка доступна наставнику/тимлиду |

Шаги — ожидаемый маршрут приёмки, не отчёт о новом запуске. Каждый отказ и расхождение
нужно сохранить с режимом и версией кода. `/demo next` меняет фикстуры; это не этап
адаптации и не настоящее согласование. Демо-состояние H1 не доказывает постоянство
после рестарта; live-имитации backend хранятся в PostgreSQL.

Демонстрационные ссылки `example.invalid` обозначают объекты синтетической команды
и не открывают настоящие корпоративные страницы. Ссылки публичного Playbook ведут
к внешнему документу. H4 проверяет текст; OCR и визуальная оценка не выполняются.

Telegram подтверждает получение H4-файла до скачивания и ожидания истории. После
скачивания показывает переход к проверке структуры/Jira. Во время H4 и обычного
LLM-запроса индикатор «печатает…» обновляется в фоне; завершение или отмена останавливает
его. Ошибка вспомогательного индикатора не отменяет основной результат. Это поведение
проверено с управляемыми задержками; фактический отклик Telegram измеряется отдельно.

### Дополнительные команды

1. `/demo` включает синтетического стажёра. Спросите «Что нового?» или отправьте `/brief`.
2. «Какие доступы нужны для ORD-118?» — статусы, источники и кнопка заявки в имитацию.
3. `/demo next` меняет шаг сценария; доступны три шага. `/demo reset` начинает заново.
4. Спросите о команде или playbook обычным текстом; `/ask` остаётся только совместимостью.
5. «Что делает /settings?» объясняет команду; `/settings brief 09:00` меняет время,
   `/settings quiet on|off` — тихий режим. При quiet on в день без изменений бриф не приходит.
6. Отправьте PDF/PPTX: бот проверяет текст до 10 МиБ и 30 слайдов. Учебные файлы:
   [fixtures/equator](fixtures/equator), сценарий — [H4_OPERATIONS.md](docs/archive/2026-11-15/H4_OPERATIONS.md).
7. `/demo mentor` и `/demo intern` переключают учебные роли; `/demo off` выходит из демо.

Для реального профиля импортируйте синтетический seed и выдайте приглашение:

```powershell
docker compose exec -T backend backend seed
docker compose exec -T backend backend invite --user demo-daniil
```

Код передаётся адресату приватно для `/start <код>`. Повторный `/start` показывает
профиль. Операции seed и приглашений подробнее описаны в [backend/README.md](backend/README.md).

## Проверки разработки

```powershell
uv sync --project agent --frozen --extra dev --python 3.12
uv run --project agent --frozen --extra dev pytest agent/tests
uv run --project agent --frozen --extra dev ruff check --config agent/pyproject.toml agent scripts infra
uv run --project agent --frozen python -m buddy --smoke
openspec validate --all
```

OpenSpec требует Node.js ≥ 22.12 и CLI `@fission-ai/openspec`.
Go-интеграции: `python infra/test_backend.py` (Go на хосте и Docker либо отдельный
`TEST_DATABASE_URL`). Покрытие: `make cover`; тесты используют фейки LLM.
Windows-окружение с ограниченным Temp: команда с `--basetemp` приведена в [agent/README.md](agent/README.md).
Реальные LLM-evals запускаются отдельно с согласованным бюджетом: [evals/README.md](evals/README.md).

Воспроизводимое покрытие из корня: `python scripts/check.py coverage` (или `make cover`).
Нужны Go, uv и Docker либо TEST_DATABASE_URL. Отчёты: `backend/coverage.out`
(statements Go) и `reports/python-coverage.xml` (строки Python). Порог >80% проверяется
отдельно. Для HTML Go: `go tool cover -html=backend/coverage.out -o backend/coverage.html`.
Критерий заказчика сформулирован для строк: стандартный Go-процент statements нельзя
выдавать за измерение строк. Соответствие этой части критерия требует отдельной проверки.
В сдаче фиксируйте дату, commit, область и инструмент измерения; старые результаты
из отчётов не являются новым прогоном финальной версии. SDD: [OpenSpec](openspec/specs),
история изменений: [openspec/changes](openspec/changes).

`infra/smoke.py` проверяет здоровье пяти обязательных сервисов и присутствующего
PowerPoint MCP. Для PPTX-стека передайте тот же набор Compose-файлов:

```powershell
python infra/smoke.py --demo --compose "docker compose -f docker-compose.yml -f docker-compose.powerpoint.yml"
```

Jira/Calendar MCP проверяются отдельно через `make mcp-list`. Здоровье контейнера
PowerPoint не подтверждает извлечение текста: для этого загрузите учебный PPTX.
Регрессионная проверка состава контейнеров без Docker: `python -m unittest infra.test_smoke`.

## Внешние API и подключение модели

Для демо без LLM достаточно fake-режима выше. Для настоящей LLM укажите в `.env`
`LLM_IN_DEMO=true`, `LLM_PROVIDER=openrouter`, `LLM_MODEL` и собственный `LLM_API_KEY`.
Провайдер OpenRouter, идентификатор модели и пример конфигурации указаны в
[.env.example](.env.example); наличие примера не подтверждает доступность модели
на дату проверки. Выбранная модель должна поддерживать используемые агентом вызовы инструментов.
Для совместимого API: `LLM_PROVIDER=compatible`, `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`.
После изменения окружения выполните `docker compose up -d --force-recreate agent`.
Вызовы расходуют API-бюджет. Секреты не передавайте в README, видео или ZIP.

В live-режиме корпоративные источники подключаются read-only по [mcp/README.md](mcp/README.md).
При сбое LLM предусмотрены правила/шаблоны; при сбое источника ответ может быть частичным.
Наличие ключа и запущенных контейнеров не заменяет проверку качества ответов.

## Совместимость с инфраструктурой и проверка пользы

Go REST/buddy-mcp проверяет права и работает с PostgreSQL; Python/LangGraph управляет
агентом, Redis используется для памяти live-диалога. Telegram и React/TypeScript-клиент
используют одного агента. Docker Compose, CI и Grafana входят в прототип. Применение
Kafka, Clickstream и конкретных frontend-библиотек не заявляется.

Для внедрения предстоит согласовать канал и обработку данных, подключить существующие
авторизацию/роли Авито и read-only источники, заменить имитацию заявок согласованным
адаптером. Корпоративное SSO не реализовано. Собственную HR-систему продукт не создаёт.

Основная метрика пилота — рутинные минуты наставника на стажёра в неделю до/после
с учётом недели стажировки, задач и времени исправления ошибок помощника. Оценки
полезности, клики и отсутствие эскалации не равны подтверждённому решению или часам.
Сейчас есть агрегаты брифов, оценок, доступов, MCP и агентных ходов. Расширение
продуктовых метрик отменено; новые события и панели исключены из плана.
Состав и ограничения: [docs/METRICS.md](docs/METRICS.md).
