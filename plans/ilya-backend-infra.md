## Зафиксированные решения
- Go: `net/http`, `pgx`, `goose`, официальный MCP Go SDK; один процесс с REST `/api/*`, MCP `/mcp`, редиректами `/r/*`.
- Слои: HTTP/MCP → прикладная логика → PostgreSQL. Для Этапа 0 внешние Go-зависимости не нужны.
- Локальный Docker Compose: PostgreSQL 16 + pgvector, Redis 7, Grafana, backend и agent.
- Аккаунты внешних сервисов ещё готовятся. Их отсутствие не блокирует каркас или будущий демо-режим.
- В полном демо backend и buddy-mcp настоящие, синтетические данные в БД; внешние MCP заменяются фикстурами. Уточнение OpenSpec согласовать с командой перед реализацией демо.
- Права: `X-Buddy-Key` для сервиса, `X-Buddy-User` для пользовательских операций; команда и роль берутся из БД.
- Только чтение корпоративных сервисов. Запись наших данных — через REST. Секреты только в локальном `.env`.
- Время в БД — UTC; повторные события и команды обрабатываются идемпотентно.

- Grafana: прочитанные брифы, брифы с переходом, «помогло» H2/H3, время до доступа, MCP-вызовы. Учётная запись Grafana только для чтения.
