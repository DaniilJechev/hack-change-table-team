# Router: синтетическая оценка Этапа 2

- `cases.jsonl`: 70 фраз, все 16 кейсов RT-01; ожидаемые task/situation/menu задаются отдельно.
- `holdout.jsonl`: отдельные 16 контрольных формулировок, по одной на кейс. Набор был просмотрен при разработке и используется как регрессионный контроль, а не как слепая оценка обобщения.
- `rules-report.json`, `holdout-report.json`: детерминированные результаты правил, confusion matrix и ошибки параметров. Датасеты не импортируются кодом Router.
- Получено 70/70 и 16/16, ошибок ожидаемых параметров 0. Это оценка правил на этих наборах, не точность реальной LLM и не пользовательский пилот.

Из корня:
```sh
uv run --project agent --frozen --extra dev python evals/run_router.py
uv run --project agent --frozen --extra dev python evals/run_router.py --dataset evals/router/holdout.jsonl
```

По умолчанию сеть не нужна. Реальная LLM — только явный `--mode llm` с локально заданными LLM_PROVIDER, LLM_MODEL, LLM_API_KEY и при необходимости LLM_BASE_URL. Токен Telegram для этой оценки не нужен. Вывод содержит только ID теста, классы и агрегаты, без текста ответа модели и ключей. Реальный LLM-прогон в этой задаче не выполнялся. В pytest LLM всегда fake/mock.

Начальная оценка показала 68/70 и 13/16. Доработаны общие правила: падеж «первого контакта», формулировка «что ты умеешь», приоритет сводки стажёров над общим словом «доступы», синонимы ответственности/эскалации. Обе итоговые оценки воспроизводятся тестами.
