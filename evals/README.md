## Эксперимент оценщика EV-01–03 (14.11)

`run_agent.py` теперь проверяет критерии `quality` во всех 34 кейсах. Это механические проверки
фактов, формулировок и URL, а не семантический судья. Успешность продукта и экономия времени
наставника ими не подтверждаются. Набор знаком разработчикам, независимым holdout он не является.

- `all`: все фрагменты; `any`: хотя бы один; `none`: запрещённые утверждения; `patterns`: все regex.
  Регистр и ё/е нормализуются для фрагментов. Regex допускают варианты фразы.
- `sources`: обязательные точные URL; `allowed_sources`: при необходимости полный белый список URL.
  Наличие URL не доказывает, что каждый факт им подтверждён.
- `allow_fallback`: разрешение запасного ответа; по умолчанию false. Fallback допустим только
  вместе с выполненными критериями содержания. Состояния и побочные действия пока не оцениваются.
- `allowed_quotes`: точные цитаты, исключаемые из языковой эвристики и поиска метаинструкций.
- `tools: []` запрещает вызовы LLM; отсутствие поля не ограничивает выбор. Лишние названия
  запрещены по умолчанию, исключение — `allow_extra_tools: true`. Повтор одного инструмента разрешён.
- `arguments`: обязательные значения аргументов по инструменту. Исполнение Registry записывается
  отдельно от запрошенных вызовов; это не проверка успеха каждого вложенного MCP-вызова.

`checks.content: null` означает «не оценено», отсутствие критериев не даёт успешного кейса.
Отдельно сохраняются полный текст (включая раскрываемые блоки), источники, исполнения и причины
провала. Известные служебные фразы, CJK и длинное переключение на английский проверяются эвристиками;
код в fenced-блоках, имена инструментов и разрешённые цитаты допускаются. Это не универсальный
детектор утечек или языка. Короткий технический ответ полностью на английском может пройти.

По умолчанию нужен успех не менее 90% кейсов, 100% прохождение критических проверок
(служебный текст, язык, запрещённые инструменты), отсутствие инфраструктурных ошибок и
неоценённых ответов. 90% — экспериментальный порог, ещё не продуктовая приёмка.
Код выхода 1 означает неполноту или провал; отчёт сохраняется до выхода.

```sh
uv run --project agent --frozen python evals/run_agent.py \
    --max-requests 100 --output evals/agent/experiment.json
uv run --project agent --frozen python evals/run_agent.py \
    --dataset evals/agent/cases.jsonl --repeats 2 --max-requests 200
uv run --project agent --frozen --extra dev pytest agent/tests/test_agent_evaluation.py
```

Модель по умолчанию берётся из `LLM_MODEL`; `--models` позволяет сравнение.
Бюджет общий на один запуск команды: все модели, повторы и подготовительные ходы, включая
неудачные HTTP-попытки. Счётчик срабатывает до отправки, не сбрасывается между кейсами.
Повторный запуск команды начинает новый бюджет: общий лимит нескольких запусков учитывайте отдельно.
`budget.responses` — полученные HTTP-ответы; `budget.cost_including_history` — известная стоимость
включая историю (если провайдер её возвращает). Нулевая стоимость при ConnectError не является
подтверждением нулевого счёта провайдера. Ключи и заголовки в отчёт не сохраняются.

Метаданные содержат commit, dirty, хеш рабочего diff, промпта, набора и оценщика и настройки
LLM. При dirty-прогоне для воспроизведения нужен экспериментальный коммит, а не только базовый HEAD.
