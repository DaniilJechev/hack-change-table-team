# Изменения Jira в персональном брифе

В live-режиме `/brief jira` использует проект из разрешённого пользователю каталога
(`target.project_key`) и Jira-идентификатор из его профиля (`logins.jira`).
Для Jira Cloud предпочтителен account ID, для Server/DC — username; email также
поддерживается, если он присутствует в ответе Jira. `JIRA_USERNAME` — аккаунт
подключения MCP, а не замена персонального `logins.jira` всех пользователей.
Синтетические `demo.daniil` и `ORD` нужно сопоставить с существующими тестовыми
объектами при настройке live-данных. Одного API-токена для этого недостаточно.

В `.env` нужны `DEMO_MODE=false`, `JIRA_URL`, `JIRA_USERNAME`, `JIRA_API_TOKEN`.
Секреты не передавайте в чат и не включайте в Git. У аккаунта MCP должны быть
права просмотра только нужного тестового проекта и его истории/комментариев.
Запуск Jira MCP описан в [README](README.md); `make mcp-up` поднимает также Calendar,
для которого требуются собственные настройки. Обычный `make up` внешние MCP не запускает.

## Содержание и период

- Статус, исполнитель, дедлайн и приоритет — отдельные пункты с «было → стало»,
  если оба значения действительно переданы Jira.
- Описание — отметка «изменилось описание» без передачи полного текста в бриф/LLM.
- Комментарии коллег в своих задачах и упоминания в других задачах — со ссылкой
  на комментарий. Недавно переназначенные с пользователя задачи также учитываются.
- Сохраняются напоминания о ближайших и просроченных дедлайнах.

Период согласован: с последнего успешно отправленного брифа; первый запуск — сутки,
в понедельник три дня. Отбор событий точный: `since < created <= now`.
Более широкий фильтр JQL по дате нужен из-за часового пояса аккаунта Jira;
в итоговый бриф лишние события не попадают. Уже доставленные пункты повторно не показываются.
Обновление своей задачи без поддерживаемых подробностей истории отображается общей
отметкой «задача обновлена», без предположений о старых значениях.

## Проверка в Telegram

После настройки реального проекта и профиля запустите `/brief jira` вне `/demo`.
В учебной задаче, назначенной на ваш Jira-аккаунт, вручную измените статус или
дедлайн и повторите `/brief jira`: появится новое изменение со ссылкой на задачу.
Агент сам ничего в Jira не меняет, включая историю просмотров (`update_history=false`).

Поиск обрабатывает Cloud page token и Server/DC offset: максимум 10 страниц по 50 задач.
Ошибка, неверный ответ или превышение лимита дают «Данные из Jira сейчас недоступны».
Не следует считать этот текст подтверждением отсутствия изменений.

Ограничение закреплённого MCP v0.24.1: `jira_get_issue(include="changelog,comments")`
возвращает доступную встроенную историю и до 100 комментариев. Метаданные полноты
истории Jira при упрощении ответа теряются; отдельный обход всех страниц истории
и комментариев здесь не реализован. Для задач с большой историей полнота всех изменений
не гарантируется. Автотесты используют синтетические ответы реального формата;
проверка с пользовательским аккаунтом Jira отдельно ещё требуется.
