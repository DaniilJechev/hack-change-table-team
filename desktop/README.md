# AvitoCode для Windows

React + Electron, Windows 10/11 x64. Один профиль, агент и новая история с
Telegram. По умолчанию приложение скрыто в трее: клик по иконке открывает
окно справа, крестик/Esc скрывают. «Выйти» в меню трея завершает процесс.
Автозапуск при входе Windows включается только в настройках.

## Сервер и ngrok

На компьютере, где работает общий стек AI-buddy:

1. Настроить `.env` по основному README: Telegram, backend и необходимые
   интеграции/LLM. Включить `CLIENT_API_ENABLED=true`.
2. Самостоятельно запустить `make up` и `make seed`. Это включает бота, если
   задан его токен. Не запускать второй polling-процесс с тем же токеном.
3. Для туннеля установить ngrok и настроить его токен вне git, затем выполнить:

   ```sh
   ngrok http 8081
   ```

4. В приложении открыть настройки и указать выданный **корневой HTTPS-адрес**,
   например `https://your-endpoint.ngrok.app`, без `/client/v1`.
5. Нажать «Войти через Telegram», отправить боту показанную команду
   `/desktop КОД` и подтвердить вход кнопкой. Код действует 5 минут.

Для учёта кликов по брифу задайте на сервере `REDIRECT_BASE_URL` равным
тому же HTTPS-адресу ngrok и перезапустите агент. Он проксирует `/r/<token>`
в backend: адрес назначения берётся только из БД. При смене туннеля обновите
и эту переменную; без неё используются прямые ссылки на источники.

Через туннель публикуется только агент: `/health`, `/client/v1` и `/r/<token>`. Не направлять
туннель на Go backend (8080), Grafana, Redis, PostgreSQL или внутренние MCP.
Доступ определяется приложением; сам HTTPS-туннель не заменяет авторизацию.
ngrok и компьютер со стеком должны продолжать работать. При смене адреса
нужно изменить настройки приложения и заново войти. Фактические лимиты и
доступность туннеля зависят от аккаунта ngrok.

LLM/API-ключи и BUDDY_SERVICE_KEY остаются в `.env` сервера. Приложение хранит
только свою сессию с защитой Windows DPAPI. Сессия действует 30 дней, выход
отзывает её. После изменения адреса старый токен новому серверу не отправляется.
Кнопка SSO — заглушка «Вход через SSO находится в разработке».

## Демо без реальных аккаунтов

Сервер: `DEMO_MODE=true`, `LLM_IN_DEMO=false`, `LLM_PROVIDER=fake`,
`CLIENT_API_ENABLED=true`. Для изолированной демонстрации оставьте токен
Telegram пустым. Существующий `.env` с настоящим токеном автоматически не менять.
После подключения к этому серверу в клиенте появится «Попробовать синтетическое
демо». Данные изолированы для каждой сессии и пропадают при перезапуске агента.
Доступны `/demo next`, `/demo reset`, `/demo mentor`, `/demo intern`.
Демо использует SeedData и фикстуры, а не PostgreSQL для истории чата.

## Сборка и установка

Нужен Node.js 24 и npm. В каталоге `desktop`:

```sh
npm ci
npm test
npm run build
npm run pack:win
```

Установщик: `desktop/release/AvitoCode Setup 0.1.0.exe`; CI также выкладывает
его как артефакт `AvitoCode-windows-x64`. Первая сборка без цифровой подписи
и автоматических обновлений; корпоративную установку согласовать отдельно.
После установки запустите AvitoCode и откройте настройки из трея.

Разработка: `npm run dev`. Только development допускает HTTP loopback,
например `http://127.0.0.1:8081`. Production требует HTTPS.

## Возможности и приёмка

- `/brief`, `/access`, `/ask`, `/stats`, `/settings`, `/reset`, `/teamcard`.
- Обычные вопросы H2/H3, источники, кнопки оценок, эскалации и ответы наставника.
- PDF/PPTX до 10 МиБ и 30 слайдов; YAML/JSON карточка команды по роли.
- Новые сообщения Telegram отображаются в desktop; старую историю Telegram
  приложение не выгружает. Ответы на live-запросы из desktop также приходят
  в привязанный Telegram-чат с источниками и кнопками; фоновые сообщения —
  в историю desktop и Telegram. Ошибка доставки в Telegram не отменяет сохранённый
  ответ в desktop. Автоматического повтора Telegram-доставки нет. Синтетическое
  desktop-демо не отправляет ответы в Telegram.
- Оригиналы вложений хранятся приватно в PostgreSQL с проверкой пользователя;
  клиент скачивает их через авторизованный API. Доступ к файлу по одному URL
  без сессии невозможен. Вложения входят в резервную копию БД.
- Операции сохраняются с идентификатором запроса. При перезапуске агента
  незавершённая операция помечается прерванной; записи автоматически не повторяются.
- Окно/уведомления работают пока процесс остаётся в трее. После полного выхода
  push-службы Windows нет; история подтянется при следующем входе.
- Windows может подавить уведомления системными настройками/«Не беспокоить».
  Уведомление не раскрывает окно само; нажатие открывает нужное сообщение.

Проверить на настоящей Windows: старт скрытым, трей и меню, повторный запуск,
resize и DPI, два монитора, отключение монитора, крестик/Esc/сворачивание,
автозапуск, ответы при скрытом и активном чате, клик уведомления, восстановление
после сна и потери ngrok, H0–H4 и вход/выход. Linux smoke не подтверждает
работу Windows Toast, автозапуска и установщика.

Контракт публичного API: [openapi.yaml](openapi.yaml).
