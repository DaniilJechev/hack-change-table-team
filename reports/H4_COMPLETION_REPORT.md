# Завершение H4 и единый формат брифа

Дата: 14 ноября 2026. Ветка: `codex/h4-completion-plan`.
Работа выполнена с тремя субагентами; результаты интегрированы и проверены основным агентом.
Предшествующие незакоммиченные изменения трассировки сохранены. Коммиты и push не выполнялись.

## Реализовано

- PDF/PPTX, строгий титул по доверенным данным, шесть разделов с содержимым.
- Проверка Jira-ключей только разрешённых проектов команды. Простые ссылки в целях/планах
  не требуют статуса; заголовок выполненных задач задаёт «готово», явный статус важнее.
  Пустые ответы, неизвестные статусы, ошибки прав/транспорта не дают ложного допуска.
- Изображения разрешены; обязательные сведения проверяются по извлекаемому тексту.
  OCR и оценка оформления не выполняются.
- Рекомендации по целям с LLM, проверкой JSON/номеров/цитат и fallback без модели.
  Рекомендательные пороги настраиваются: 10 слайдов и 100 слов по умолчанию.
- Версии, сравнение исправленных/оставшихся/новых замечаний, различение изменения Jira
  при повторе того же файла. Новые загрузки сразу инвалидируют старые кнопки.
- Live-история через REST в PostgreSQL, миграция `00008_equator_history.sql`.
  Демо-история в SQLite в постоянном томе, без backend; изолирована по владельцу демо.
- Настраиваемый срок истории `H4_HISTORY_TTL_DAYS=7`, диапазон 1–36500 дней;
  проверки и кнопки недействительны после истечения срока.
- Отдельные состояния доставки файла и отчёта; подтверждённо доставленные части
  повторно не отправляются. Неизвестный исход требует явного повтора с предупреждением.
- Отметка трекера означает проверку AI-buddy; доставка учитывается отдельно.
  Адрес собственного наставника восстанавливается через защищённый REST после рестарта.
- Подсказки H4 без LLM, `/help`, разбиение длинного отчёта без обрезания замечаний.
- Бриф и «Ещё N» используют общий формат без кружков. Проверенный текст ежедневного
  брифа сохраняется вместе с пунктами; повтор и восстановление не требуют новой LLM.
  Одиночный ответ-бриф не переформулируется вторым агентным проходом.

Спецификации H4, REST-истории и формата брифа опубликованы через OpenSpec.
Эксплуатация и параметры: [архив H4_OPERATIONS.md](../docs/archive/2026-11-15/H4_OPERATIONS.md). Подробности backend: `H4_BACKEND_COMPLETION.md`.

## Запущенный бот

Финальный образ запущен и оставлен работать в Docker Compose вместе с backend/PostgreSQL,
Redis и PowerPoint-MCP. Контейнер agent healthy, Telegram getMe успешно вернул
`avito_furry_bot`: https://t.me/avito_furry_bot . Режим `DEMO_MODE=true`, `LLM_IN_DEMO=true`,
срок истории 7 дней. Хеш `buddy/equator/history.py` внутри контейнера совпал с рабочим деревом.
Для проверки включите `/demo`; нужны лишь синтетические презентации, реальные аккаунты Jira не нужны.
Docker Desktop должен оставаться запущенным.

## Что остаётся нерешённым и как решить

| Ограничение | Последствие | Следующий шаг |
|---|---|---|
| Живая Jira не принята на реальных аккаунтах | Fixture/REST-тесты не доказывают интеграцию с конкретной Jira | Настроить разрешённые проекты, учётку только чтения и прогнать реальные статусы/ошибки прав |
| Поддержан один polling-worker | Восстановление `sending` не рассчитано на несколько одновременно отправляющих процессов | Добавить lease с worker token, временем и атомарным продлением; затем тестировать несколько workers |
| Длинный отчёт хранит состояние целиком | При частичной доставке явный повтор может повторить ранние сообщения отчёта | Хранить checkpoint каждого сообщения; сейчас частичная доставка получает unknown и предупреждение о копиях |
| Физическая очистка истории выполняется при обращении | Истёкшие записи сразу недоступны, но могут лежать в БД до следующей операции | Добавить периодический sweeper PostgreSQL и SQLite с тестом физического удаления без запросов |
| LLM проверяется по схеме и цитатам | Смысловая ошибка рекомендации всё ещё возможна | Расширить размеченный eval-набор, ручное ревью, измерять выдуманные замечания и пропуски |
| Имена/заголовки/статусы распознаются правилами | Нестандартная формулировка может потребовать уточнения | Дополнять подтверждёнными примерами словари и тесты; не ослаблять допуск угадыванием |
| Нет даты экватора | Нельзя честно добавить «экватор через N дней» в бриф | Согласовать поле даты в профиле; напоминание §10.3 — отдельная задача, не часть §10.5 |
| Одноисточниковый быстрый бриф не сохраняется | Его продолжение после рестарта не восстанавливается | При необходимости согласовать постоянное хранение быстрых ответов; ежедневный бриф уже сохраняется |

Минуты экономии наставника не заявляются без замера. История позволяет считать загрузки,
разные файлы и подтверждённую доставку; отдельный аналитический дашборд H4 не добавлялся.
Ручной Telegram-прогон пользователя остаётся приёмкой пользовательского опыта.

## Как проверить

1. Открыть бота, включить `/demo`.
2. Отправить `fixtures/equator/bad.pdf`, затем `good.pdf` и проверить сравнение.
3. Нажать «Отправить наставнику»: в демо файл и отчёт приходят в тот же чат.
4. Повторить нажатие; затем загрузить плохую версию и проверить, что старая кнопка недействительна.
5. Запросить `/brief`, открыть «Ещё N» и сравнить формат.

Исходные файлы стажёра не редактируются. Реальные корпоративные сервисы остаются только для чтения.
