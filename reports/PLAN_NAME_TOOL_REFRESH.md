# План: имя человека в ответе без инструмента → обязательный вызов инструмента

**Статус:** план, код не менялся. **Дата:** 13.11. **Ветка:** `feat/agent-orchestrator`.
**Решение:** согласование с Даниилом пропускаем (решение Эмиля, 13.11). Остальные открытые пункты (`reports/PLAN_CLOSE_OPEN_ISSUES.md`: доступы, ложные срабатывания `TASK`/`PR`, формат истории, память по треду, сноски) **не закрываем**.

## Проблема (воспроизведено в Telegram 13.11, 10:52–10:54)

1. «привет» → агент вызвал `team_q3` и `brief_now`, ответ со сносками.
2. «кто мой наставник?» → ответ «Наставник — Анна. Она же твой первый контакт.»
   - инструмент не вызван, ссылок нет — модель пересказала первый ответ из истории;
   - факт **неверный**: первый контакт — Олег (в истории: «тимлид и первый контакт … — Олег»);
   - `verify` пропустил: на ходе без инструментов он ловит только ключи задач и номера PR.

## Цель

Если на ходе без инструментов в ответе есть имя человека из карточки команды, ответ не показывается. Модель получает **одну** попытку с обязательным вызовом инструмента команды и отвечает по свежим данным со ссылками. Если не вышло — прежний запасной путь (FR-AG-05: Router → Executor).

**Готово, когда:** диалог «привет» → «кто мой наставник?» в Telegram даёт во втором ответе вызов `team_q3`, верного первого контакта (Олег) и сноски `[1]`, `[2]`.

## Как работает

```
шаг 1: модель ответила без инструментов
  └─ verify: прежние проверки (URL, метки, ключи, PR) → как сейчас
  └─ имя из карточки в ответе?
       ├─ нет → ответ показывается
       └─ да  → Rejected("name"), повтора ещё не было?
            ├─ да  → шаг 2: + ответ модели (assistant) + служебное сообщение,
            │        tools = только инструменты команды, tool_choice = "required"
            │        → инструменты выполняются, результаты с метками S#
            │        → шаг 3: обычный шаг (все инструменты, без required) → verify → сноски
            └─ любой сбой на шагах 2–3 → FR-AG-05: Router → Executor
```

- Шагов по-прежнему `MAX_STEPS = 3`: повтор возможен только на шаге 1, поэтому он ровно один.
- Если на шаге 3 модель снова вызовет инструмент → `steps` → результат первого инструмента (со ссылками). Это приемлемо.
- Ответ модели с шага 1 пользователю не показывается и в память не пишется (в память пишется только итоговый ответ после guard, как сейчас).

## Решения и допущения

1. **Любое имя, а не только «имя + роль».** Так просили: имя → актуализировать. Следствие: «спроси у Анны, как устроено ревью» тоже вызовет повтор. Цена — +1–2 запроса и +2–4 с, зато совет придёт со ссылкой на Анну. Ложного отказа без ответа не будет.
2. **Имена — из карточки команды**, `runtime.data.team_card(context.user_id)["document"]["people"]`, без LLM. Демо — seed-карточка `seed/team_cards/demo-orders.yaml`, живой режим — backend.
3. **Свое имя пользователя исключается** (`person.user_id == context.user_id`): «Привет, Даниил» не должно вызывать повтор.
4. **Падежи:** основа имени — имя без конечной `а`/`я`/`й`/`ь`, совпадение `\b<основа>\w{0,3}\b` с заглавной буквы: «Анна/Анны/Анне/Анной», «Олег/Олега/Олегом». Длина основы ≥ 3, иначе ищем имя целиком.
5. **Карточка не прочиталась** (ошибка данных) → проверка имён пропускается, ход идёт как сейчас. Карточка читается только когда модель ответила без инструментов.
6. **На повторе — только инструменты команды** (`team_q1`–`team_q8`): проверка 13.11 показала, что `required` со всеми инструментами вызывает лишние (`brief_now` на «Привет!»). На шаге 3 — снова все инструменты роли.
7. **`tool_choice: "required"`** с `provider.require_parameters: true` (добавить в существующий `provider: {"data_collection": "deny"}`, не заменять): OpenRouter не отправит запрос провайдеру, который молча игнорирует параметр. Для DeepSeek V4.1 Flash проверено 13.11 (4 живых запроса, `reports/plan_agent_tool_retry.md`).
8. **Таймаут хода** `TIMEOUT = 20 с` не меняется: повтор с `team_q*` — около 2 шагов по 1–2 с, инструменты команды без LLM.

### 2. `agent/buddy/agent/loop.py` (~30 строк)
- Константа `TEAM_TOOLS = {name for name in TOOLS if name.startswith("team_q")}`.
- Функция `async def people_names(context, runtime) -> list[str]`: имена из карточки без своего; любая ошибка → `[]`.
- Функция `mentions(answer, names) -> bool` — правило падежей из п. 4.
- В `Agent.answer`, ветка `if not calls:`
  - сначала прежний `verify(...)` (без изменений);
  - затем, если `not done` (инструментов в ходе не было) и `mentions(answer, await people_names(...))`:
    - если повтор уже был → `Rejected("name")` → запасной путь;
    - иначе: `messages += [{"role": "assistant", "content": reply["content"]}, {"role": "user", "content": RETRY}]`, флаг `retried = True`, следующий шаг цикла вызывает `llm.chat(messages, team_tools, tool_choice="required")`.
- `RETRY` — служебный текст: «В этом ходу ты не вызвал инструменты, а ответ называет людей команды. Вызови инструмент команды и ответь по его результату с метками источников; прошлые ответы из истории не подходят.»
- Лог: `agent retry: name` (только причина, без текста — как `agent fallback`).
