## Что умеет бот

1. Стажёр присылает презентацию в **PDF или PPTX**. Формат определяется по расширению и сигнатуре файла.
2. Бот извлекает текст по слайдам и проверяет два обязательных критерия **без LLM**:
   - **Структура** — шесть разделов учебной структуры по словарю синонимов заголовков;
   - **Факты** — каждый ключ задачи (`ORD-118`) существует в Jira, а статус, написанный рядом на слайде,
     совпадает со статусом в Jira.
3. Ответ — список ✅ / ⚠️ / ❌ с номерами слайдов. Ссылки на задачи берутся из ответа Jira (их ставит код).
4. Сам файл не меняется: бот пишет «исправьте замечания и пришлите новую версию».
5. Если оба критерия пройдены — «Готово к показу наставнику» и кнопка **[Отправить наставнику]**. По нажатию:
   - `mark_progress(user_id, "equator_presentation")` в имитации трекера (в демо — SeedData, без HTTP);
   - наставник получает тот же файл из Telegram (по `file_id`) и отчёт проверки;
   - стажёр видит статус этапа. Повторное нажатие не меняет время первой отметки.

Не делаем: оценку оформления, рекомендации «Цели» и «Форма», репетицию речи, сравнение версий.

## Как читается файл

| Формат | Чем | Почему |
|---|---|---|
| PDF | `pypdf` 6.x внутри агента | чистый Python, без системных пакетов; заголовок — первая строка страницы |
| PPTX | готовый MCP-сервер [GongRzhe/Office-PowerPoint-MCP-Server](https://github.com/GongRzhe/Office-PowerPoint-MCP-Server) 2.0.7 (MIT, ~1.8k ★, самый популярный) | поручение лида: найти MCP для PowerPoint, вырезать запись, оставить чтение — по образцу GitHub, Jira и Calendar |

### Как вырезана запись в PowerPoint-MCP

Upstream регистрирует около 30 инструментов, большинство создают, меняют или сохраняют файлы.
Обёртка [`mcp/powerpoint/entrypoint.py`](../mcp/powerpoint/entrypoint.py) работает по образцу Calendar,
где вырезан `manage-accounts`:

- версия с PyPI зафиксирована в `mcp/powerpoint/requirements.txt`;
- при старте из реестра FastMCP удаляется всё, кроме `open_presentation` и `extract_presentation_text`;
- если устройство реестра upstream изменилось, сервер не запускается (проверка выполняется и при сборке образа);
- `open_presentation` принимает только имя `.pptx`-файла внутри `PPTX_ROOT`: `../` и абсолютные пути отклоняются;
- из ответа убран путь файловой системы сервера; в памяти хранится не больше 20 открытых презентаций.

Защита со стороны агента — второй рубеж, как у остальных серверов: `READ_TOOLS["powerpoint"]` и белый
список кейса `equator_check` (`jira_get_issue` + два инструмента PowerPoint) в `buddy/mcp_hub/policy.py`.

### Запуск

- Отдельный overlay `docker-compose.powerpoint.yml`: сервер не требует корпоративных аккаунтов, поэтому не
  зависит от секретов Jira и Google в `docker-compose.mcp.yml`.
- `make pptx-up` — стек с PowerPoint-MCP, `make pptx-list` — проверка `tools/list` (ровно два инструмента).
  В `make mcp-up` и `make mcp-list` сервер тоже включён.
- Агент и сервер передают файл через общий том `presentations` — это tmpfs (uid 10001), на диск файлы не
  попадают. Агент кладёт файл `<sha256>.pptx`, вызывает два инструмента и сразу удаляет файл.
- В демо (`DEMO_MODE=true`) учебные PPTX читаются из записанных фикстур сервера (`fixtures/step_*/powerpoint/`),
  ключ фикстуры — sha256 файла. Для своего PPTX фикстуры нет: тогда агент читает его локальным контейнером
  PowerPoint-MCP, если задан `PPTX_MCP_URL` (его задаёт `docker-compose.powerpoint.yml`). Корпоративный аккаунт
  для этого не нужен. Без контейнера бот просит прислать PDF. PDF в демо — любой.

## Правила проверок (черновик, синтетика — не регламент Авито)

**Структура.** Заголовок слайда нормализуется: нижний регистр, «ё» → «е», без нумерации, эмодзи и знаков по
краям. Раздел найден, если заголовок совпадает с синонимом или начинается с него; при нескольких совпадениях
побеждает самый длинный синоним. Порядок разделов не проверяется.

| Раздел | Синонимы |
|---|---|
| Титул | слайд 1, если есть ≥ 3 из 4 признаков: наставник, команда, стажёр/стажировка, период (два месяца или две даты) |
| Цели стажировки | цели стажировки; цели; мои цели; цели на стажировку; ожидания от стажировки |
| Выполненные задачи | выполненные задачи; что сделано; что я сделал; сделанные задачи; проделанная работа; мои задачи |
| Результаты | результаты; итоги; что изменилось; эффект для команды; результаты в цифрах |
| Сложности и чему научился | …; сложности; трудности; чему научился; чему я научился; уроки |
| Планы до конца стажировки | …; планы; дальнейшие планы; следующие шаги; что дальше |

**Факты.** Ключ `[A-Z][A-Z0-9]+-\d+`; статус берётся из слов в той же строке.

| Группа | На слайде | В Jira |
|---|---|---|
| Готово | готово, сделано, выполнено, закрыта, done | Done, Closed, Resolved |
| В работе | в работе, в процессе, делаю, in progress | In Progress |
| На ревью | на ревью, на проверке, review | In Review, Code Review |
| В планах | в планах, запланировано, to do, todo | To Do, Open, Backlog |

✅ — статус совпал (или на слайде он не назван, а задача есть); ⚠️ — статус расходится; ❌ — задача не найдена
(Jira вернула ошибку инструмента по ключу, в демо — для ключа нет фикстуры). Если Jira недоступна, результат
«не проверено», и кнопки нет. Презентация без ключей задач факты не проходит.

## Как проверить в Telegram

1. Стек поднят: `make pptx-up` (или команда выше).
2. В личном чате с ботом: `/demo`.
3. Отправить `bad.pdf` или `bad.pptx` → список ❌/⚠️ со слайдами, кнопки нет.
4. Отправить `good.pdf` или `good.pptx` → «Готово к показу наставнику» и [Отправить наставнику].
5. Нажать кнопку → в чате появляется копия для наставника (файл + отчёт; в демо все участники в одном чате)
   и «Этап «Презентация к экватору» … ✅ отмечен».
6. Свой PDF и свой PPTX проверяются в демо полностью (PPTX — через контейнер `powerpoint-mcp`).

## Решения, которые стоит согласовать

1. **«Задача не найдена»** = ошибка инструмента Jira по ключу (в демо — нет фикстуры). Недоступность Jira
   — «не проверено».
2. **Свой PPTX в демо** читается локальным контейнером PowerPoint-MCP (решение Эмиля 13.11): демо при этом
   по-прежнему не требует корпоративных аккаунтов, но для своего PPTX нужен запущенный `powerpoint-mcp`.
3. **Зоны.** Правки `docker-compose.powerpoint.yml`, `Makefile`, `infra/mcp_probe.py`, `mcp/` — зона Ильи;
   генератор фикстур, фикстуры и черновик спецификации — зона Даниила.
