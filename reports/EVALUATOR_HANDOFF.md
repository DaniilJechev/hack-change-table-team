## Исходные проблемы оценивания

Старая оценка в основном проверяла выбор инструментов. Из 34 кейсов только один имел expect; отсутствие критериев автоматически считалось успехом. tools: [] не запрещал инструменты. Аргументы не проверялись, answered не означал правильный ответ, скрипт всегда возвращал 0. Ответ с китайской служебной строкой «回答前不需要调用工具。» проходил все старые проверки.

H2 проверял правила и подстроки, H3 — поиск источника, а не ответ LLM. Отдельные evals H0/H1 отсутствовали; H4 не проходил полный путь файла и доставки. Пользовательскую экономию времени наставника текущие evals не измеряют.

## Что реализовано

1. Все 34 кейса получили quality: обязательные фрагменты all, варианты any, запрещённые none, regex patterns, ожидаемые точные URL sources. Поддерживаются allowed_sources, allowed_quotes и allow_fallback.
2. Отсутствие критериев даёт not_evaluated, а не pass. Содержание, получение ответа и выбор инструментов разделены.
3. tools: [] запрещает вызовы модели; отсутствующее tools не ограничивает выбор. Лишние названия запрещены, если нет allow_extra_tools. Для задач добавлены проверки аргумента task.
4. Записываются предложенные вызовы и завершённые исполнения Registry отдельно. Сохраняются полный ответ с раскрываемыми блоками, URL и результаты проверок.
5. Добавлены эвристики служебных фраз и языка, регрессия со скриншота. Есть контрольные ошибочные ответы: неверный наставник, статусы, неполнота, выдуманный факт, неверная ссылка и отказ.
6. Общий RequestBudget ограничивает HTTP-попытки до отправки и не сбрасывается между моделями, кейсами, повторами и подготовительными ходами. Отдельно считаются полученные HTTP-ответы и известная стоимость с историей.
7. Отчёт содержит commit, dirty, хеши промпта/набора/оценщика/рабочего diff, настройки и инфраструктурные ошибки. Код выхода 1 при неполноте или провале.
8. По умолчанию порог 90% успешных кейсов, критические проверки должны пройти все. Это экспериментальный порог, не утверждённая продуктовая приёмка.
9. Исправлена ошибка Reasons: agent retry больше не считается fallback.

Эти отчёты **не оценивают качество DeepSeek**. Они фиксируют отказ сети и fallback. Не использовать их tools/pass/answered как метрики реальной модели. Нулевая известная стоимость не доказывает состояние биллинга провайдера.

Службы: CodexSandboxService.OpenAI.Codex уже Running, com.docker.service Stopped. Попытка Start-Service com.docker.service отклонена правами. Ничего не было успешно запущено. Evals вызывают Agent/Registry напрямую в Python на фикстурах: Docker, backend и работающий Telegram-бот им не нужны.

Не повторять десятки вызовов, пока не проверено восстановление сети. Не обходить ограничения среды неразрешённым способом.

## Известные ограничения нового оценщика

- Подстроки и regex не являются семантической проверкой: могут пропустить отрицание, неверные связи и бессмысленный ответ с нужными словами.
- Ожидаемый URL не доказывает, что каждый факт подтверждён именно им.
- Языковые/стилевые эвристики могут ошибаться. Короткий английский ответ может пройти, валидная формулировка — получить ложный fail.
- Завершение Registry не равно успеху каждого вложенного MCP-вызова.
- Fallback по умолчанию запрещён для оценки качества агента; успешность запасного сценария нужно отдельно покрывать кейсами с allow_fallback и содержательными критериями.
- Набор известен разработчикам, слепым holdout не является.
- Не добавлены полные H0/H1/H4 и семантический судья: выполнен только первый этап.
- Git metadata фиксирует dirty и хеш diff, но для незакоммиченных/новых файлов сам по себе хеш не заменяет сохранение исходников.

Продолжай автономно в рамках запроса. Не выдавай сетевые отказы за проверку качества бота и не превышай оставшиеся 130 попыток LLM.
