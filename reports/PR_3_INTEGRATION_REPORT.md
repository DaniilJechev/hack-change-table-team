# Отчёт по PR №3: инфраструктура Ильи

Дата: 10 ноября 2026. PR: https://github.com/DaniilJechev/hack-change-table-team/pull/3

## Исходная ситуация
PR №2 с общим каркасом уже был слит в main. PR №3 был создан от более ранней версии: значительная часть файлов добавлена независимо, возникли 16 конфликтов add/add. Ветка PR №3 объединена с актуальным main; изменения проверены совместно.

## Принято из PR №3

| Изменение | Итог и причина |
|---|---|
| Go-сервер с Read/Write/Idle timeout | Перенесён в backend/internal/server; используется действующим backend. Ограничивает время работы соединений. |
| Graceful shutdown с ожиданием завершения | Принят context.AfterFunc, ожидание окончания Shutdown и принудительный Close при истечении таймаута. |
| Проверки HTTP, закрытого listener и занятого порта | Сохранены и объединены с тестами main; проверяется реальное поведение сервера. |
| Расширенный smoke | Принят infra/smoke.py: ровно пять running/healthy контейнеров, HTTP/JSON приложений, Grafana, Redis PONG, SQL с типом vector и DEMO_MODE. |
| read_only и init | Файловые системы backend/agent только для чтения; agent запускается через init. Проверено с настоящим агентом, а не заглушкой. |
| Отключение аналитики Grafana | Приняты три настройки отключения телеметрии и проверок обновлений. |
| Улучшения CI | Добавлены gofmt, go vet, race detector, таймауты job и отдельный smoke демо-режима. Сохранены воспроизводимые зависимости main. |
| Удобные команды | Добавлены make ps, logs, check-config, validate-specs и dev; make ingest/record-fixtures завершаются явной ошибкой до реализации. |
| План Ильи и история OpenSpec | Сохранены с пояснением, что исходные результаты относятся к его отдельной ветке. |
| Дополнительные gitignore | Приняты исключения egg-info и Go test-бинарников; дубли правил убраны. |

## Принято с адаптацией
- Smoke проверяет текущий контракт status/service/stage=0; не требует устаревшего mode=stub.
- Go-сервер использует существующий api.Handler: две конкурирующие реализации /health не создаются.
- OpenSpec scaffold уточнён отдельным изменением integrate-backend-infra; действующие требования H0–H3 не изменены.
- Команды Makefile и проверка покрытия сохраняют совместимость с Windows; проверки сделаны на Python вместо обязательных awk/mkdir и SHELL=/bin/sh.
- README, AGENTS.md и статус roadmap приведены к фактической реализации. Изменены статусы и инструкции, не продуктовые требования.

## Не принято

| Предложение исходной ветки | Почему |
|---|---|
| Заменить agent на buddy.stub и Docker-образ без зависимостей | Это удалило бы уже работающие /start, /help, LLM-клиент, FakeLLM и pydantic-схемы. Сохранён агент main. |
| Вернуть README к утверждению «Telegram и LLM не реализованы» | Уже не соответствует main и подтверждённой живой проверке бота. |
| Требовать mode=stub от обоих приложений | Противоречит существующему контракту и режимам offline/telegram. |
| Заменить pyproject и установку зависимостей без lockfile | Потеря нужных зависимостей и воспроизводимости. Сохранён uv.lock. |
| Переименовать Go module в ai-buddy/backend и поднять минимум Go до 1.27 | Для принятых улучшений не требуется; сохранены существующие import paths и Go >=1.24. |
| Заменить всю конфигурацию Compose | Сохранены рабочие порты, env, демо по умолчанию, Grafana provisioning и текущие пароли/тома. Добавлены только совместимые улучшения. |
| Обязательный POSIX shell и awk в Makefile | Эти команды ухудшают переносимость для текущей Windows-среды. |
| Автоматически обновить Grafana и версии Actions вместе со слиянием | Независимые обновления не нужны для совместимости двух каркасов; проверенные версии main сохранены. |

Эти решения относятся к интеграции с текущим main: исходная заглушка была допустима для отдельной backend-задачи Ильи.

## Проверено
- Python 3.12: 37 тестов; покрытие agent 99.4%.
- Go: 9 тестовых функций, включая таблицы HTTP; покрытие backend 86.7% statements (после добавления серверного жизненного цикла).
- Ruff, gofmt и go vet; OpenSpec валидируется.
- Локальный Compose: пять сервисов healthy с read_only; HTTP/JSON, Grafana, Redis, vector и DEMO_MODE проходят новый smoke.
- CI является обязательной проверкой перед слиянием PR №3; race detector выполняется на Linux runner.

## Что остаётся за пределами этого слияния
H0–H3, MCP-интеграции, PostgreSQL-модель пользователей и привязка Telegram реализуются на следующих этапах. Анкета подготовлена, реальные ответы стажёров ещё не собраны. Реальные LLM-вызовы не выполнялись.
