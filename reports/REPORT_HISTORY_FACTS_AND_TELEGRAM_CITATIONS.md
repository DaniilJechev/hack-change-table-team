## Задача 1. Агент отвечает фактами из истории без инструментов

### Было
- Если в истории диалога уже был ответ, модель переписывала его и не вызывала инструменты.
- `verify` требовал метки `[S#]` только при наличии источников; без инструментов `sources` пуст — проверка пропускала любой текст.
- Проверка «выдуманного PR/задачи» сверяла номера с `observed`, а он начинался с текста пользователя: «PR #47» из вопроса считался известным.
- Eval `agent-030` («Что у меня нового?» → «а кто ревьюит PR #47?»), DeepSeek: инструментов 0, ссылок 0, ответ принят:
  > Не вижу в брифе, кто назначен ревьюером по PR #47 — там сказано только, что он ждёт твоего ревью…

### Стало
- **Промпт** (`agent/buddy/agent/loop.py`, `SYSTEM`): факты — только из инструментов, вызванных *в этом ходу*; прошлые ответы в истории не источник.
- **Код** (одна строка в `Agent.answer`): если в ходе не выполнялся ни один инструмент, `verify` получает пустой `observed`. Любой ключ задачи Jira или номер PR — даже из вопроса или истории — отклоняется → FR-AG-05: Router → Executor.
- Общий совет без ключей и PR («как лучше начать первый день?») проходит без инструментов, как и раньше.
- Eval `agent-030`, DeepSeek, после исправления: вызван `brief_now`, 1 ссылка:
  > По данным брифа видно только, что PR #47 «ORD-119: учебный клиент Kafka» ждёт твоего ревью [1]. Кто ещё его ревьюит — в брифе не указано…
- Спецификация: дельта FR-AG-09 в `openspec/changes/agent-orchestrator/specs/agent-orchestrator/spec.md` и 2 сценария («Факт из истории без инструментов», «Общий совет без инструментов»); в `proposal.md`, п. 1г — «реализовано, ждёт согласования».
- Тесты (`agent/tests/test_agent_orchestrator.py`): `test_fr_ag_09_followup_from_history_without_tools_is_not_shown`, `test_fr_ag_09_fact_from_question_without_tools_is_rejected` (PR и ключ задачи), `test_fr_ag_09_general_advice_without_tools_passes`.

### Не закрыто
- **Имена людей и статусы доступов кодом не проверяются.** Агенту доступна только роль, карточка команды в `verify` не попадает, а простые имена встречаются и в общих советах. Сценарий из Studio («Кто мой наставник?» → «Анна» из истории) закрыт только промптом. Критерий приёмки «факт из карточки команды без инструмента отклоняется» выполнен для ключей задач и PR, но не для имён.
- Возможны ложные срабатывания: `TASK` совпадает со строками вида `UTF-8`, `#12` считается PR. Последствие — ответ уходит в Router, неверный текст не показывается.
- `store.history()` не менялся: пометка «устарело» в истории поменяла бы формат FR-MEM-04, а модель могла бы её копировать.
- Повторная проверка в Studio с двумя тредами не делалась; проверено eval-кейсом в одном диалоге.

## Задача 2. Ссылки — сноски `[1]`, `[2]` в формате Telegram

### Было
- Ответ заканчивался блоком «Источники:» с голыми URL; больше 3 ссылок — свёрнутая цитата.
- Бриф:
  ```
  1. 🔴 Git: PR #45 «ORD-118: фильтр по статусу» — запрошены изменения (demo-anna)
  …
  Источники:
  <blockquote expandable>https://…/pull/45#pullrequestreview-9001
  …ещё 4 URL…</blockquote>
  ```
- «Кто мой наставник?» — три строки, затем «Источники:» и 2 URL.

### Стало
- Сноска ставится в конце той строки, где использован источник: `<a href="URL">[n]</a>`. Блока «Источники» нет.
- Нумерация сквозная, по первому упоминанию; один URL — один номер. URL берутся только из `ExecutorResponse.links`; сноска без ссылки удаляется.
- Экранирование: текст — `html.escape(quote=False)`, `href` — `quote=True`.
- Бриф:
  ```
  1. 🔴 Git: PR #45 «ORD-118: фильтр по статусу» — запрошены изменения (demo-anna) <a href="https://example.invalid/github/…/pull/45#pullrequestreview-9001">[1]</a>
  2. 🟠 Jira: ORD-118 «Учебная проверка заказов» — вас упомянули (demo.oleg) <a href="https://example.invalid/jira/browse/ORD-118?focusedCommentId=5001">[2]</a>
  ```
- «Кто мой наставник?» (Олег — тимлид и первый контакт, номер [2] не дублируется):
  ```
  Ваш наставник — Анна. <a href="…/people/demo-anna">[1]</a>
  Тимлид — Олег. <a href="…/people/demo-oleg">[2]</a>
  Первый контакт в неожиданных ситуациях — Олег. <a href="…/people/demo-oleg">[2]</a>
  ```
- Доступы: сноска у каждого инструмента, включая строки под свёрткой «Доступ есть (4)»; номера идут в порядке чтения.
- Ответ агента: метки `[S#]` → `[n]` (как раньше) → кликабельные сноски. Live-прогон `agent-015`: 8 ссылок, каждая у своего факта.

### Как устроено
- `render.cite()` расставляет сноски кодом. Ответ, где сноски уже есть (агент, доступы, команда, playbook), не трогается. Если нумерованные строки совпадают со ссылками 1:1 (бриф), сноска ставится у каждой строки. Иначе все сноски — в конце последней строки ответа (ответ одним абзацем).
- `cite()` вызывают три места: guard графа (`graph/build.py`), `to_html` и `to_plain`. Повторный вызов ничего не меняет. Это нужно, потому что расписание брифа, кнопки брифа и заявки на доступ идут в Telegram мимо графа.
- Исполнители, где строка = ссылка, ставят сноски сами: доступы (статус, задача, монитор) и команда (q1, q2, q3, q8). Playbook ставит сноски после ответа, до пометки «Playbook — публичный документ».
- Агент видит результаты инструментов без сносок (`_observe` их вырезает), чтобы не путать их со своими метками `[S#]`.
- Запасной вариант без HTML (`TelegramBadRequest`) — `to_plain`: те же сноски и список `[n] URL`, не длиннее 4096 символов, обрезка только по границе строки.
- Демо-режим и пути без LLM работают: все тесты на фикстурах зелёные.
- Спецификация: новое изменение `openspec/changes/telegram-citations/` — ADDED FR-UI-03, MODIFIED FR-UI-01 (убран пункт «Источники > 3 свёрнуты»). Архивировать после `live-run-fixes`.
- Тесты: `agent/tests/test_telegram_citations.py`, 13 тестов `test_fr_ui_03_*` (вставка, дедупликация, без источников, экранирование, длинный ответ, бриф, свёрнутый блок, агент, playbook, доступы и команда). Тесты, проверявшие «Источники», обновлены; `test_fr_ui_01_long_source_list_is_folded` удалён вместе со сценарием.

### Не закрыто
- Отдельного ограничения длины HTML нет: если HTML длиннее 4096, Telegram отклонит его, и уйдёт простой текст (≤ 4096).
- Напоминание о последнем брифе после «Изменений нет» (B-15) вместе с «Ближайшим» событием: ссылок на одну больше, чем строк, поэтому сноски уходят в конец ответа.
- Если в тексте исполнителя уже есть `[n]` (например, в FAQ), `cite()` считает сноски расставленными и новых не добавляет.
- team q4 и q6 (две ссылки в одном предложении) и ответы с одной ссылкой получают сноски в конце ответа.
- `executors/core.py:render()` ещё пишет «Источники», но вызывается только из тестов; не трогали.
- В Studio `outbox` по-прежнему дописывает строки `[n] URL` (это не Telegram).

### Стало
- Если на ходе без инструментов в ответе есть имя человека из карточки команды (в любом падеже, кроме имени самого пользователя), ответ не показывается. Модель получает **один** повторный шаг: только инструменты команды (`team_q1`–`team_q8`) и `tool_choice: "required"`, затем обычный шаг. Ответ идёт по свежим данным со сносками.
- Повтор не помог (снова имя без инструмента, ошибка LLM или провайдера) → прежний запасной путь: Router → Executor.
- Карточка не прочиталась → проверка имён пропускается.
- `CompatibleLLM.chat(..., tool_choice=…)` добавляет `tool_choice` и `provider.require_parameters: true` к `data_collection: deny`. Без `tool_choice` тело запроса не меняется.
- В логе: `agent retry: name` (только причина).

### Файлы
- `agent/buddy/agent/loop.py`: `TEAM_TOOLS`, `RETRY`, `mentions()`, `people_names()`, повтор в `Agent.answer` (~35 строк).
- `agent/buddy/llm/client.py`: аргумент `tool_choice` у `FakeLLM` и `CompatibleLLM`; `FakeLLM.choices` для тестов.
- Спецификация `openspec/changes/agent-orchestrator/`: FR-AG-09 (имя из карточки), FR-AG-05 (повтор), 4 сценария; `proposal.md` п. 1г, `tasks.md` 5.4.
