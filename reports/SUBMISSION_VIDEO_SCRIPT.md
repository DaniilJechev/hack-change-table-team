# Сценарий демовидео AI-buddy

Подготовлен 15.11.2026. Плановая длительность — 3 минуты; официального ограничения
длительности в переданных критериях нет. Это план записи, не протокол выполненного прогона.
Основной экран — Telegram, синтетический стажёр Даниил. Все пять H0–H4 входят в ролик.

## Режим и подготовка

Базовый воспроизводимый вариант: DEMO_MODE=true, LLM_IN_DEMO=false,
LLM_PROVIDER=fake, RAG_SEARCH_MODE=bm25. Нужен токен отдельного Telegram-бота.
Корпоративные аккаунты и LLM-ключ не нужны, но Telegram требует соединения с сетью.
Это демонстрация сценариев с правилами и шаблонами; её нельзя назвать проверкой качества LLM.
При записи с настоящей моделью явно заменить подпись режима и выполнить предварительный
прогон с её конфигурацией. Не переключать режим незаметно между кадрами.

1. Выполнить маршрут из README; убедиться, что этим токеном пользуется один polling-процесс.
2. Отправить `/demo`, затем `/demo reset`. Убедиться, что активен первый шаг.
3. Открыть `fixtures/equator/bad.pdf` и `good.pdf`, подготовить их к отправке.
4. Сделать пробный прогон всех кадров. После него снова `/demo reset`.
5. Включить режим «Не беспокоить», скрыть посторонние переписки и уведомления.
6. Не выводить .env, токены, приглашения и приватные данные. Сохранить сведения
   о режиме, версии кода и файлах в SUBMISSION_CHECKLIST.md.

## Пошаговые действия ведущего

Ниже — порядок записи экрана. Озвучка и монтажный тайминг приведены далее; реальные
ожидания могут занять больше трёх минут. Сначала записать весь маршрут, затем монтировать.

### 0. Подготовить чат и файлы

1. Открыть личный чат с настроенным ботом. В сессии запуска 15.11.2026 проверен
   `@avito_furry_bot`; перед новой записью сверить, что используется нужный экземпляр.
2. Текущий запущенный в этой сессии сервис использует `DEMO_MODE=true` и
   `LLM_IN_DEMO=true`: для такой записи подпись должна быть «Синтетические данные,
   настоящая LLM». Базовый вариант без LLM из раздела выше требует отдельной настройки.
   Не менять окружение и не перезапускать сервис посреди записи.
3. Отправить `/demo`, дождаться ответа. Затем отправить `/demo reset`, дождаться
   подтверждения первого шага. Сброс очищает свою демо-историю, включая H4.
4. Открыть в проводнике папку `fixtures/equator` из корня репозитория. Подготовить
   `bad.pdf` и `good.pdf`. Отправлять их как документы через скрепку → «Файл».
5. Перед началом очистить поле ввода. Не менять роль: весь основной ролик идёт от стажёра.

### 1. H0: показать бриф

1. Отправить `/brief`. Дождаться сообщения с заголовком и главным действием.
2. На несколько секунд оставить видимыми главное действие и первые пункты.
3. Если есть кнопка «Ещё …», нажать её один раз и показать дополнительные пункты.
   Точное число пунктов брать из интерфейса, не подставлять число из сценария.
4. Показать ссылки-сноски у пунктов. Не переходить по `example.invalid`: это учебные
   адреса, они не откроют настоящие Jira/Miro/GitHub.
5. Вернуться к нижней части чата для следующего запроса. Не отправлять `/demo next`.

### 2. H1: найти недостающий доступ

1. Отправить ровно: `Какие доступы нужны для ORD-118?`
2. Дождаться ответа. Найти Miro / «Доска планирования» и статус отсутствующего доступа.
   Если модель задала уточняющий вопрос, выбрать именно эту доску и дождаться статуса.
3. Показать имя объекта, источник и кнопку «Запросить доступ: …» для Miro.
   Предупреждение о запрещённом production-объекте не означает, что его нужно запрашивать.
4. Если Miro уже доступен, не продолжать сцену с заявкой: выполнить `/demo reset`
   и повторить путь с начала. Это возвращает фикстуры первого шага.

### 3. H1: отправить заявку и показать ожидание

1. Нажать **кнопку заявки у Miro** под ответом. Не нажимать ссылку-сноску и
   «Где запросить»: ссылка открывает адрес, а не вызывает программную заявку.
2. Дождаться сообщения вида «Сервис доступов (имитация): заявка на согласовании».
   Оставить его на экране на несколько секунд.
3. Снова отправить `Какие доступы нужны для ORD-118?`.
4. Показать строку Miro и сохранённое состояние «на согласовании» / `pending`.
   На этом этапе доступ ещё не согласован. Не говорить «доступ получен».

### 4. H1: фиктивно согласовать заявку

1. В том же чате от того же пользователя отправить **`/demo next` один раз**.
   Отдельного экрана согласования и кнопки тимлида в этом Telegram-маршруте нет.
   Команда переключает синтетический сценарий с первого на второй шаг и имитирует
   результат согласования. В кадре оставить команду или добавить понятный титр.
2. Дождаться подтверждения «Шаг 2/3». Может появиться отдельное уведомление о Miro.
3. Повторить `Какие доступы нужны для ORD-118?`.
4. Показать у Miro «доступ есть» и результат имитации «доступ выдан» / `granted`.
   Это повторное чтение состояния после действия.
5. Остаться на втором шаге до конца ролика. Второй `/demo next` здесь не нужен.
6. Если вместо результата осталось ожидание, проверить, что запрос был сделан на
   первом шаге и команда отправлена в той же сессии. При расхождении повторить
   сцену после `/demo reset`; не подменять ответ в монтаже.

Фраза для ведущего: «Теперь имитируем решение согласующего командой демо-перехода.
Повторный запрос показывает результат. Настоящие права в Miro мы не меняем».

### 5. H2: найти маршрут в команде

1. Отправить `Упал staging, кому писать?`.
2. Дождаться полного ответа. Показать маршрут из карточки команды, ответственного
   и ссылку на источник. В учебной карточке есть `#orders-duty` и Олег.
3. Озвучивать фактически показанный ответ. Не переходить в настоящий чат и никому
   не писать: здесь демонстрируется поиск маршрута, а не эскалация инцидента.

### 6. H3: найти практику в Playbook

1. Отправить `Что такое Zero Bug Policy?`.
2. Дождаться ответа, показать найденный материал, ссылки и пометку публичного документа.
3. Без LLM озвучить «найденные фрагменты»; при настоящей LLM — «ответ по найденным
   материалам». Не обещать одинаковую формулировку в двух режимах.
4. Если нужен кадр открытого источника, заранее проверить ссылку публичного Playbook,
   затем открыть её, показать раздел и вернуться в Telegram. Этот переход необязателен.

### 7. H4: получить замечания к плохой версии

1. Нажать скрепку → «Файл», выбрать `fixtures/equator/bad.pdf` и отправить документ.
   Не отправлять скриншоты слайдов и не вставлять локальный путь обычным сообщением.
2. Показать раннее сообщение «Презентация получена. Подготавливаю проверку…».
3. Дождаться статуса «Проверяю презентацию: структура и задачи в Jira…», затем отчёта.
   Во время долгого ожидания показать индикатор; ускорение при монтаже подписать.
4. Прокрутить отчёт и задержаться на одном структурном замечании и замечании по
   Jira, если они присутствуют. Не озвучивать заранее придуманные номера слайдов.
5. Убедиться, что плохая версия не предлагается к отправке наставнику. Не нажимать
   старую кнопку отправки из предыдущих репетиций.

### 8. H4: показать исправленную версию

1. Вставить титр «После самостоятельной доработки». В ролике используются две
   заранее подготовленные учебные версии, а не запись редактирования файла агентом.
2. Через скрепку → «Файл» отправить `fixtures/equator/good.pdf`.
3. Между двумя загрузками **не отправлять `/demo reset`**: он удалит историю сравнения.
4. Дождаться отчёта. Показать сравнение с предыдущей проверкой и результат
   обязательных критериев. Рекомендации могут оставаться и после допуска.
5. Найти кнопку «Отправить наставнику» именно под новой успешной проверкой.
   Если допуска нет, проверить выбранный файл и фактические замечания; не заявлять успех.

### 9. H4: подтвердить передачу

1. Нажать «Отправить наставнику» под отчётом `good.pdf` один раз.
2. Дождаться результата. В Telegram-демо копия файла и отчёт появляются в том же чате.
3. Показать итоговый статус доставки. Добавить титр «Демо-доставка в этот же чат».
4. Если появилась только отметка трекера, а доставка не подтверждена, не говорить,
   что файл доставлен. Показать фактическую ошибку и повторить после устранения причины.

### 10. Проверить ограничение роли и закончить

1. Не переключая роль, отправить `/interns`.
2. Показать отказ: сводка доступна наставнику или тимлиду.
3. Закончить титром о пилоте и репозитории. Не показывать процент экономии как результат.
4. После записи сохранить исходное видео; проверить читаемость текста, звук и отсутствие
   секретов. Подготовить финальную версию и добавить рабочую ссылку в README/PDF.

### Команды в порядке записи

```text
/demo
/demo reset
/brief
Какие доступы нужны для ORD-118?
[нажать кнопку заявки Miro]
Какие доступы нужны для ORD-118?
/demo next
Какие доступы нужны для ORD-118?
Упал staging, кому писать?
Что такое Zero Bug Policy?
[отправить bad.pdf]
[отправить good.pdf]
[нажать «Отправить наставнику» под новой проверкой]

```

Строки в квадратных скобках — действия мышью, их не нужно отправлять сообщениями.

## Что фиксировать отдельно

- Чтобы доказать идемпотентность, в репетиции повторить исходное нажатие заявки до
  `/demo next`. Сопоставить результат с тем же объектом; отсутствие дубля сообщения
  само по себе не доказывает отсутствие дубля заявки. При необходимости показать
  эту проверку в расширенной демонстрации, не жертвовать читаемостью основного ролика.
- Демо-сессия H1 не доказывает сохранность после рестарта. Постоянное хранение backend
  проверяется отдельно; в озвучке этого обещания нет.
- Проверку H4, отметку имитации трекера и доставку считать разными исходами.
- `/demo next` — команда ведущего для фикстур, не этап онбординга и не действие согласующего.
- Отказ `/interns` показывает одно ограничение роли, не полную проверку межкомандной изоляции.

## Правила записи и резерв

- Захват 1920×1080, крупный текст; озвучку записать по фактически полученным ответам.
- Набор и ожидание можно сократить, пометив ускорение. Не заявлять по монтажу отклик <1 с.
- Не открывать example.invalid как работающий сервис. Рабочую внешнюю ссылку можно
  показывать только после отдельной проверки и с сохранением пометки о публичном Playbook.
- Замечания bad.pdf не подменять текстом сценария; оставлять фактические результаты.
- При сбое записи повторить сцену после восстановления и сброса состояния; не подменять
  ответ картинкой. Для живой защиты иметь локальную копию готового ролика.
- Если запись не укладывается в 3 минуты, увеличить длительность при отсутствии лимита
  организаторов. Не обрезать сохранённый результат H1 и существенные пометки.

## Проверка готового ролика

- [ ] H0–H4 видны, основной H1 проходит от запроса до повторного чтения результата.
- [ ] Имитация, режим LLM и синтетические данные обозначены.
- [ ] H4 содержит обе версии, самостоятельную доработку и честную подпись доставки.
- [ ] Есть проверка ограничения роли; нет ложного утверждения об экономии часов.
- [ ] Ссылка доступна без запроса дополнительных прав; локальная копия воспроизводится.
- [ ] Ссылка добавлена в README и на первый слайд финального PDF.
