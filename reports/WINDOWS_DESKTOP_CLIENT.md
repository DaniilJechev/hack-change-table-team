# AvitoCode: реализация Windows-клиента

Дата: 14 ноября 2026. Ветка: `feat/desktop-windows-client`.
Основа: `main` обновлён через `git pull --ff-only`, коммит `6c53235`.
Согласованный план: [windows-desktop-client.md](../plans/windows-desktop-client.md).

## Что реализовано

- Electron 45 + React/TypeScript: скрытый запуск в трей, одно окно/один процесс,
  панель справа около трети рабочей области, resize, always-on-top, сохранение
  размеров, адаптация к мониторам. Закрытие, сворачивание и Esc скрывают окно.
- Настройки HTTPS-сервера, ngrok, вход через Telegram с подтверждением,
  одноразовые коды на 5 минут и отзываемые сессии на 30 дней. Смена адреса
  прекращает старое подключение и требует нового входа. SSO — заглушка.
- Общий ChatService и новая история Telegram/desktop, одна live-память агента.
  Сообщения, действия и файлы используют текущий AgentService, H0–H4,
  права и списки инструментов. Собственной LLM-логики в клиенте нет.
- Фоновые события сохраняются в личную историю и доставляются Telegram;
  ответ на обычный запрос идёт в исходный канал. API доступен при
  `CLIENT_API_ENABLED=true`, по умолчанию функция выключена.
- SSE с возобновлением, idempotency операций, отображение ошибок и прерывания
  после перезапуска без автоматического повторения действий записи.
- Уведомления из main-процесса при скрытом/неактивном чате, в том числе когда
  открыты настройки; нажатие открывает сообщение. Восстановление старой
  истории не создаёт уведомлений. История читается только при реальном показе
  сообщения в активном окне, а не при её загрузке из API.
- Оценки скрывают пару реакций, сохраняя раскрытие остальных пунктов и другие действия.
- Загрузка PDF/PPTX, JSON/YAML карточек команды, оригиналы и отчёты H4,
  передача презентации наставнику. Неопределённая доставка не повторяется
  без явного подтверждения пользователя.
- Авторизованное получение вложений. Оригиналы хранятся в PostgreSQL в
  приватных записях канала; байты не попадают в поток событий. Это позволяет
  обойтись без отдельного хранилища для небольшого пилота. Лимит файла —
  10 МиБ; при росте объёма можно заменить хранение оригиналов адаптером.
- Проксирование `/r/<token>` в Go для ссылок брифа через один ngrok-туннель;
  назначение берётся только из БД, служебный ключ внешнему адресу не передаётся.
- Изолированные синтетические demo-сессии на SeedData и фикстурах. Демо не
  использует PostgreSQL для переписки и не предоставляет live-вход.
- Windows NSIS installer и отдельная Windows-задача CI; ключи сервисов остаются
  на сервере. Renderer изолирован, Node отключён, токен доступен только main,
  сохранение сессии использует OS safeStorage (Windows DPAPI).

## Контракты и запуск

- [Инструкция клиента и ngrok](../desktop/README.md).
- [Публичный OpenAPI](../desktop/openapi.yaml).
- [Служебный OpenAPI backend](../backend/openapi.yaml), `/internal/client/{operation}`.
- Миграция `00009_desktop_channel`: устройства, сессии, записи и события канала.
- OpenSpec: `windows-desktop-client` (изменение оставлено открытым до Windows-приёмки).

Туннель направляется на порт агента 8081. Для учёта кликов `REDIRECT_BASE_URL`
задаётся равным публичному HTTPS-адресу. Go backend, БД, Grafana и MCP наружу
не публикуются. Локальный backend клиент самостоятельно не устанавливает.

## Проверки

- Полные Go-тесты с настоящим изолированным PostgreSQL и race detector прошли;
  покрытие backend **90,2%**, `go vet` прошёл.
- Полный Python-прогон и целевые регрессии общего канала прошли; общее покрытие
  агента **около 95%**; финальный полный прогон — **772 passed**.
- TypeScript, Vite production build, Prettier и 7 тестов оконной геометрии,
  URL/ссылок и политики уведомлений прошли.
- Electron smoke на Linux: скрытый старт, наличие трея, изоляция preload,
  always-on-top, resize и закрытие в трей. Сквозной synthetic API smoke:
  реальный HTTP `/brief` → общий агент → SSE → React прошёл.
- Полный synthetic smoke не проверяет OS-хранилище сессии: использует временный
  профиль и токен только в памяти. Windows DPAPI требует отдельной приёмки.
- OpenAPI обоих API проверен `openapi-spec-validator`; OpenSpec strict valid,
  полный validate — 31 passed; Compose config и `git diff --check` прошли.
- Windows x64 NSIS установщик собран на Linux. Артефакт находится в
  `desktop/release/AvitoCode Setup 0.1.0.exe` (сборки исключены из git).

## Что требует Windows-приёмки

Сборка не запускалась на настоящей Windows. Нужно установить EXE и проверить:

1. Трей, рамку/resize, масштабирование, расположение справа и два монитора.
2. Toast, переход к сообщению, системное «Не беспокоить», автозапуск и DPAPI.
3. Вход через настоящий привязанный Telegram, общий диалог и роли пользователей.
4. H0–H4 через общий сервер/ngrok, включая доставку презентации наставнику.

CI workflow добавлен, но удалённый GitHub Actions в рамках этой работы не запускался.
Установщик без подписи и автообновления. Рабочий бот, реальная LLM и корпоративные
аккаунты при проверках не запускались. Тестовый API использовал пустой Telegram token.

Поддерживается один экземпляр agent; координация нескольких реплик не входит в MVP.
После полного выхода из приложения отдельной Windows push-службы нет: сообщения
подтягиваются при следующем запуске. Общая история начинается с включения нового
канала, старые сообщения Telegram автоматически не импортируются.
