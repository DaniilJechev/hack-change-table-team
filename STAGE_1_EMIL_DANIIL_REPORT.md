## 4. Почему в roadmap появился Даниил

Проверены git log, git blame и diff истории docs/3_ROADMAP.md, а также импортированная переписка Claude.

1. Участие Даниила было уже в первом коммите документации bf81b3aec89c24b3ab9e3e19d10ad0c11eb662ac (10 ноября, 16:37 по Москве), подготовленном с Claude. Там описана роль PM/team lead, помощь на всех участках и отдельные задачи данных/спецификаций/оценки.
2. Сравнение этого коммита с main b35005e показывает ровно одно дополнение roadmap: статус технической готовности Этапа 0. Роли, распределение задач и сроки при недавних слияниях не менялись.
3. В исходной переписке ты просил: «я в принципе буду им помогать по всему пути, поэтому не надо меня отдельно выделять». Итоговый документ соблюдает это непоследовательно: общий абзац говорит о помощи, а таблицы содержат отдельные поручения Даниилу.
4. Это неточное оформление твоей роли в исходном плане. Нельзя считать его новым согласованным назначением обязанностей. Сейчас задачи Даниила выполняются по твоему новому прямому поручению в этом чате.

В этой ветке роли roadmap не переписаны молча. Источник роли — исходный документ, а не техническая необходимость MCP и не новое назначение при merge PR №3.

## 6. Что остаётся после получения аккаунтов

1. Серверы и REST Ильи уже приняты в PR №5; настроить настоящие read-only credentials в локальном .env.
2. Создать учебные объекты по seed/LIVE_SETUP.md и передать их реальные ID.
3. Выполнить discover --live, подтвердить имена и схемы официальных серверов; отсутствие инструмента считать блокером, а не угадывать замену.
4. Пройти auth-miro --live в viewer-аккаунте и проверить content_item_list_roles.
5. Выполнить четыре tools/call, записать безопасные ответы --live --record и проверить replay.

До выполнения этих пунктов полный Этап 1 по исходным live-критериям roadmap не считается завершённым. По уточнённому поручению «код и фикстуры» подготовлена независимая проверенная часть.
