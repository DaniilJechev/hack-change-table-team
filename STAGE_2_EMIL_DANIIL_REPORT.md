## 1. Границы поручения

Выполнены Router, каркас Executors и демо-переключение (Эмиль), а также evals Router, карточка команды и каталог доступов (Даниил). Сохраняется согласованный режим имитации на синтетических фикстурах.

Полноценные H0–H3, расписание, проверки доступов и эскалация человеку относятся к следующим этапам и здесь не выдаются за реализованные. ## 2. Что реализовано за Эмиля

| Область | Результат |
|---|---|
| Router | Закрытый список Case/RT-01, промпт, Pydantic/JSON-контракт, проверка параметров, отсутствие confidence-порогов |
| Правила | Команды и ключевые слова, извлечение task и situation; неоднозначность → clarify, постороннее → out_of_scope |
| LLM-ветка | Опциональная; доверенные роль/команда передаются отдельно от текста, user_id в промпт не передаётся. Ошибка/невалидный JSON/лишние поля/таймаут до 20 секунд → правила |
| Безопасность маршрута | Параметры user_id/team_id/role отклоняются; неизвестный кейс → out_of_scope. Вход ограничен 4000 символами |
| Реестр Executors | 16 маршрутов + прямые brief_render/access_events. Бизнес-ответы пока честные шаблоны; неизвестный кейс безопасно обрабатывается |
| Инструменты | Единые белые списки по кейсам, ограничение в 3 попытки, запрет полномочий в аргументах и сведения о запрете без содержимого запроса |
| Ответы | Строгий ExecutorResponse, source_id вместо URL от модели; ссылки подставляет код из доверенного каталога. Невалидная схема или неизвестный источник → шаблон |
| Telegram | /ask с 8 кнопками; callbacks без Router; обычный текст только после профиля backend или явного synthetic-демо. Группы и сообщения без пользователя отклоняются |
| Демо | /demo, next/reset/off; разные пользователи имеют разные шаги, последний шаг не зацикливается; максимум 256 сессий в памяти, после рестарта сброс |
| Replay | Снимок шага на операцию, точный ключ server/tool/arguments, отсутствие фикстуры не открывает сеть. В live-режиме /demo запрещён |

Демо использует публичный учебный профиль demo-daniil/intern/demo-orders и не создаёт и не меняет реальную привязку. Привязанный пользователь вне демо получает роль и команду только из backend. Реализация buddy-mcp остаётся задачей Ильи; каркас инструментов проверен фейковым gateway, а не выдан за работающий Go MCP.

Пакетный снимок `agent/buddy/demo/data` включается в существующий Docker build context агента. Его генерирует `seed/build_stage_two.py`; тест сравнивает файлы с корневыми fixtures побайтово. Dockerfile и Compose не менялись.

## 3. Что реализовано за Даниила

- Полная карточка demo-orders: 4 человека, роли, зоны, первый контакт, маршруты staging/Kafka, правила прямого обращения, стек и ссылки на 5 сервисов.
- Каталог Backend-стажёра: 5 базовых объектов, владельцы, инструкции/ссылки запроса и отдельный запрещённый production-объект с объяснением.
- Добавлен синтетический Пётр в seed/users.yaml (системная роль mentor); обновлены карточка/каталог и проверка ссылок на пользователей своей команды.
- Pydantic-контракты и cross-reference проверки team_id, владельцев, external_id, ссылок, обязательных ролей, запретов и количества инструментов.
- README, архитектура и roadmap согласованы с фактической областью работ.

## 4. Почему 16 кейсов, а не 17

В исходном roadmap и архитектуре стояло число 17, но RT-01 и уже существующий Literal Case содержат 16: brief_now, access_status, access_task_analysis, interns_status, team_q1–team_q8, playbook_qa, help, clarify, out_of_scope. Источник истины не расширялся придуманным маршрутом. Число в документации исправлено; brief_render/access_events — два дополнительных прямых триггера, всего в реестре 18 исполнителей.

## 5. Тесты и оценка — без реальной LLM

Локально: **262 pytest-теста успешно**, покрытие agent **99.3%** (1218/1227 операторов coverage), в том числе Router и контракты данных — 100%.
Ruff и форматирование проходят. Проверены также прежние тесты Этапов 0–1.

| Оценка правил | Итог |
|---|---|
| Основные 70 фраз | 70/70, accuracy 100%, ошибок ожидаемых параметров 0 |
| Контрольные 16 фраз | 16/16, accuracy 100%, ошибок ожидаемых параметров 0 |

Это результаты правил на конкретных синтетических наборах, а не измерение точности настоящей LLM. Контрольный набор просмотрен при разработке, используется как регрессионный контроль и не является слепым holdout. Датасеты не читаются production-кодом Router. Начальные результаты 68/70 и 13/16 помогли уточнить общие правила; подробности в evals/router/README.md.

LLM-ветка проверена FakeLLM и AsyncMock: валидный/невалидный JSON, неизвестный кейс, попытка передачи полномочий, timeout, исключение и отмена. Запросов к реальному LLM API не было. Явный `--mode llm` подготовлен только в evals; его запуск не выполнялся. Telegram-тесты работают через настоящий aiogram Dispatcher и OfflineSession без сети.

CI кода: https://github.com/DaniilJechev/hack-change-table-team/actions/runs/42875555276 — tests, compose и mcp успешно. Включены Go race, PostgreSQL, проверка покрытия, Ruff, offline smoke, OpenSpec, запуск образа агента с пакетными демо-данными и сквозная REST-привязка. Контейнеры CI временные и не содержат Telegram-токена. Go-код не изменён; порог покрытия backend проверен CI.

## 6. Что принято, а что исключено

Принято: отдельная ветка от последней main; схема из спецификации; одинаковые фикстуры для разработки, тестов и контейнера; роль только из профиля; ограничения инструментов до вызова gateway; явная маркировка имитации.

Не включено в реализацию: backend Ильи, реальные аккаунты и внешние API-вызовы, настоящая LLM-оценка, бизнес-логика H0–H3, живые Telegram-отправки, выдача доступов, реальные эскалации. Эти возможности не обозначаются готовыми в интерфейсе. Кнопка «Спросить наставника» явно объясняет, что связаться нужно самостоятельно.
