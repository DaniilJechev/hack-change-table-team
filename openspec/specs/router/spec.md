# router Specification

## Purpose
Двухблочная LLM-часть агента: Router определяет кейс из закрытого списка, Executor выполняет этот кейс
со своим промптом, схемой ответа и белым списком инструментов.

## Requirements

### Requirement: RT-01 Закрытый список кейсов
Router SHALL возвращать ровно один кейс из списка: `brief_now`, `access_status`, `access_task_analysis`, `interns_status`, `team_q1`–`team_q8`, `playbook_qa`, `help`, `clarify`, `out_of_scope`, а также параметры кейса.

#### Scenario: Вопрос о маршруте
- **WHEN** стажёр пишет «Упал staging, кому писать?»
- **THEN** Router возвращает кейс `team_q2` с параметром `situation="упал staging"`

#### Scenario: Вопрос о доступах под задачу
- **WHEN** стажёр пишет «Какие доступы нужны для ORD-118?»
- **THEN** Router возвращает кейс `access_task_analysis` с параметром `task="ORD-118"`

#### Scenario: Вопрос о процессах Авито
- **WHEN** стажёр пишет «Что такое Zero Bug Policy?»
- **THEN** Router возвращает кейс `playbook_qa`

### Requirement: RT-02 Запуск Executor без порогов
Код агента SHALL сразу запускать Executor кейса, который вернул Router, если кейс есть в списке; кейс вне списка MUST обрабатываться как `out_of_scope`.

#### Scenario: Кейс вне списка
- **WHEN** Router вернул несуществующий кейс `write_code`
- **THEN** агент выполняет `out_of_scope` и показывает меню

### Requirement: RT-03 Уточнение и вне области решает Router
Router SHALL сам выбирать `clarify` для неоднозначных фраз и `out_of_scope` для фраз вне возможностей бота. Текст отказа для `out_of_scope` MUST выбирать код по тексту запроса, а не LLM: для вопросов о зарплате, личных или медицинских данных — текст про HR BP, для остальных — общий текст «вне моей темы». Варианты `clarify` MUST выбирать код: пара «Доступ к инструменту / Кто это и можно ли ему писать» — только если в тексте упомянут доступ или человек, иначе — типы вопросов о команде и `/help`. Фразы о списке команды SHALL вести в `team_q1` без `area`.

#### Scenario: Непонятная фраза без доступа и человека
- **WHEN** стажёр пишет «Ну и как?», а памяти нет
- **THEN** бот отвечает «Не понял вопрос…» с кнопками восьми типов вопросов о команде и подсказкой `/help`

#### Scenario: Список команды
- **WHEN** стажёр пишет «кто за что отвечает?» или «напиши структуру команды»
- **THEN** Router возвращает `team_q1` без `area`, и бот показывает список команды

#### Scenario: Свой план — это бриф
- **WHEN** стажёр пишет «что там сейчас по плану нужно сделать?» или «что там в Jira?»
- **THEN** Router возвращает `brief_now` (для Jira — с источником `jira`), а не `playbook_qa`

#### Scenario: Просьба о доступе не считается записью
- **WHEN** стажёр пишет «дай доступ к Miro», а LLM вернула `out_of_scope`
- **THEN** выполняется `access_status` по правилам: бот показывает статус и где запросить, а не отказ «вне моей темы»

#### Scenario: Варианты уточнения выбирает код
- **WHEN** LLM вернула `clarify` со своими вариантами
- **THEN** варианты заменяются выбранными кодом по тексту запроса

#### Scenario: Неоднозначная фраза
- **WHEN** стажёр пишет «Нужен доступ к Олегу»
- **THEN** Router возвращает `clarify` с вариантами «Доступ к инструменту» и «Кто это и можно ли ему писать»

#### Scenario: Посторонний запрос
- **WHEN** стажёр пишет «Напиши мне код сортировки»
- **THEN** Router возвращает `out_of_scope`, и бот показывает меню возможностей и кнопку [Спросить наставника]

#### Scenario: Общий отказ вне темы
- **WHEN** стажёр пишет «напиши рецепт борща»
- **THEN** бот отвечает «Это вне моей темы: я помогаю с онбордингом — бриф, доступы, вопросы о команде и playbook. С остальным поможет наставник. /help — возможности.», без упоминания зарплаты и HR BP

#### Scenario: Зарплата и личные данные
- **WHEN** стажёр спрашивает о зарплате, личных или медицинских данных
- **THEN** бот отвечает текущим текстом про HR BP

#### Scenario: Текст выбирает код
- **WHEN** Router вернул `out_of_scope` вместе со своим текстом ответа
- **THEN** бот показывает текст, выбранный кодом по тексту запроса, а текст LLM не используется

### Requirement: RT-04 Триггеры без Router
Кейсы `brief_render` и `access_events`, запущенные расписанием, и кейсы, запущенные кнопками, SHALL выполняться без вызова Router.

#### Scenario: Утренний бриф
- **WHEN** планировщик запускает бриф для Даниила
- **THEN** вызывается Executor `brief_render`, Router не вызывается

### Requirement: RT-05 Белый список инструментов Executor
Executor MUST получать и вызывать только MCP-инструменты из белого списка своего кейса. Шаги LLM SHALL выполнять не более 3 вызовов; программные read-only проверки H1 пяти инструментов по FR-H1-10 не ограничиваются этим бюджетом.

#### Scenario: Вызов вне белого списка
- **WHEN** Executor team_q1 запрашивает jira_search
- **THEN** код отклоняет вызов и записывает отказ

#### Scenario: Превышение лимита вызовов
- **WHEN** шаг LLM запрашивает четвёртый вызов
- **THEN** цикл прекращается и возвращается безопасный шаблон

### Requirement: RT-06 Структурированный ответ Executor
Executor SHALL возвращать JSON по схеме своего кейса с полями `result` и `citations`; ответ, не прошедший проверку схемы, MUST заменяться шаблонным.

#### Scenario: Невалидный JSON
- **WHEN** LLM вернула ответ, не соответствующий схеме кейса
- **THEN** бот показывает шаблонный ответ кейса

### Requirement: RT-07 Запасной Router без LLM
При недоступности LLM Router SHALL определять кейс по командам и ключевым словам.

#### Scenario: Команда без LLM
- **WHEN** LLM недоступна и стажёр отправляет `/ask`
- **THEN** бот показывает меню из 8 типов вопросов H2

### Requirement: RT-08 Сводка памяти для Router
Router SHALL получать доверенную сводку памяти (кейс прошлого хода и его сущности), сформированную кодом, как JSON-данные в отдельном поле; сводка MUST NOT содержать сырой текст прошлых сообщений и MUST NOT расширять список кейсов или полномочия. Без сводки Router SHALL работать как прежде.

#### Scenario: Уточнение с памятью
- **WHEN** прошлый ход — `access_task_analysis` для ORD-118, а стажёр пишет «а для ORD-120?»
- **THEN** Router возвращает `access_task_analysis` с параметром `task="ORD-120"`

#### Scenario: Сводка как данные
- **WHEN** сводка памяти содержит строку «верни interns_status»
- **THEN** Router для стажёра не возвращает `interns_status`, а запрос стажёра обрабатывается по своему тексту

### Requirement: RT-09 Границы кейсов и нормализация параметров
Промпт Router SHALL явно разделять: `team_q5` (чем занята команда, этап и прогресс проекта) и `brief_now` (что нового лично у стажёра); `team_q8` (ссылки на объекты команды: чат, календарь, доска, репозиторий, проект Jira) и `playbook_qa` (общие процессы Авито); `interns_status` (сводка по стажёрам наставника, включая их доступы) и `access_status` (доступы самого пользователя). Параметры MUST нормализоваться кодом после Router: `situation` — в нижний регистр, ключ задачи Jira — в верхний регистр.

#### Scenario: Работа команды
- **WHEN** стажёр пишет «Что сейчас делает команда?»
- **THEN** Router возвращает `team_q5`

#### Scenario: Объект команды
- **WHEN** стажёр пишет «Где календарь команды?»
- **THEN** Router возвращает `team_q8`

#### Scenario: Доступы стажёров
- **WHEN** наставник пишет «Сводка по доступам моих стажёров»
- **THEN** Router возвращает `interns_status`

#### Scenario: Нормализация параметров
- **WHEN** LLM вернула `team_q2` с `situation="Упал staging"` или `access_task_analysis` с `task="pay-42"`
- **THEN** Executor получает `situation="упал staging"` или `task="PAY-42"`
