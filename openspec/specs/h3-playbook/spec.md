# h3-playbook Specification

## Purpose
RAG по публичному AvitoTech Playbook (H3): бот отвечает на вопросы о структуре, процессах и культуре
техкоманд Авито по снимку репозитория https://github.com/avito-tech/playbook, со ссылкой на файл и раздел.

## Requirements

### Requirement: FR-H3-01 Индекс по снимку playbook
Скрипт индексации SHALL разбивать файлы снимка playbook на фиксированном коммите на фрагменты по заголовкам markdown и сохранять для каждого текст, файл, заголовок и URL на GitHub с якорем в файл индекса, который поставляется вместе с агентом. Для режимов поиска `vector` и `rrf` скрипт MUST дополнительно сохранять эмбеддинг каждого фрагмента в таблицу `rag_chunks` (pgvector).

#### Scenario: Индексация
- **WHEN** запускается `make ingest`
- **THEN** в индексе появляются фрагменты, у каждого заполнены файл, заголовок, URL и текст

#### Scenario: Повторная индексация
- **WHEN** индексация запускается повторно на том же коммите
- **THEN** число фрагментов не меняется, дублей не появляется

#### Scenario: Индексация с эмбеддингами
- **WHEN** `make ingest` запускается при `RAG_SEARCH_MODE=rrf`
- **THEN** в таблице `rag_chunks` столько же строк, сколько фрагментов в индексе, и у каждой есть эмбеддинг

### Requirement: FR-H3-02 Ответ по найденным фрагментам
Ответ SHALL строиться только по найденным фрагментам и MUST содержать ссылку на файл и раздел на GitHub; ссылки проверяет код.

#### Scenario: Zero Bug Policy
- **WHEN** стажёр спрашивает «Что такое Zero Bug Policy?»
- **THEN** бот отвечает 2–5 предложениями со ссылкой на `development-principles.md` и раздел о Zero Bug Policy

#### Scenario: Структура компании
- **WHEN** стажёр спрашивает «Что такое юнит и кластер?»
- **THEN** бот отвечает со ссылкой на `structure.md`

### Requirement: FR-H3-03 Отказ при отсутствии ответа
Если лучшие фрагменты не покрывают вопрос — в вопросе есть слово, которого нет во всём playbook, либо близость лучшего фрагмента ниже порога режима, — бот SHALL отвечать «В playbook этого нет» и MUST показывать кнопку [Спросить наставника]. LLM MAY дополнительно отказаться, если найденные фрагменты не отвечают на вопрос.

#### Scenario: Вопрос вне корпуса
- **WHEN** стажёр спрашивает «Какой пароль от Wi-Fi в офисе?»
- **THEN** бот отвечает «В playbook этого нет» с кнопкой [Спросить наставника]

#### Scenario: Фрагменты не отвечают на вопрос
- **WHEN** LLM возвращает, что найденные фрагменты не содержат ответа
- **THEN** бот отвечает «В playbook этого нет» с кнопкой [Спросить наставника]

### Requirement: FR-H3-04 Пометка об актуальности
Каждый ответ H3 SHALL содержать пометку, что playbook — публичный документ и может быть устаревшим.

#### Scenario: Любой ответ
- **WHEN** бот отвечает по playbook
- **THEN** в конце ответа есть пометка об актуальности

### Requirement: FR-H3-05 Запасной вариант без LLM
При недоступности LLM бот SHALL показывать три лучших найденных фрагмента со ссылками.

#### Scenario: LLM недоступна
- **WHEN** стажёр спрашивает «Как часто релизы?», а LLM не отвечает
- **THEN** бот показывает три фрагмента из `processes-and-standards.md` со ссылками

### Requirement: FR-H3-06 Режимы поиска
Режим поиска SHALL выбираться переменной окружения `RAG_SEARCH_MODE`: `bm25` (поиск по словам, значение по умолчанию), `vector` (эмбеддинги и pgvector) или `rrf` (объединение обоих списков по Reciprocal Rank Fusion). В режиме `bm25` модель эмбеддингов MUST NOT загружаться в память, а база данных MUST NOT использоваться. В режимах `vector` и `rrf` модель MUST загружаться лениво — при первом вопросе по playbook; при недоступности модели или базы поиск MUST продолжать работать в режиме `bm25`.

#### Scenario: Режим bm25
- **WHEN** задан `RAG_SEARCH_MODE=bm25` и стажёр задаёт вопрос по playbook
- **THEN** бот отвечает, а библиотеки эмбеддингов не импортируются

#### Scenario: Режим rrf
- **WHEN** задан `RAG_SEARCH_MODE=rrf`, эмбеддинги проиндексированы и стажёр спрашивает «Что такое Zero Bug Policy?»
- **THEN** лучший фрагмент — раздел о Zero Bug Policy из `development-principles.md`

#### Scenario: База недоступна
- **WHEN** задан `RAG_SEARCH_MODE=rrf`, а pgvector не отвечает
- **THEN** бот отвечает по поиску `bm25` и один раз пишет предупреждение в журнал

### Requirement: FR-H3-07 Уточнения по playbook
Уточняющий вопрос по playbook SHALL переформулироваться с учётом истории в самостоятельный запрос перед поиском (правилами или LLM со схемой и откатом на правила). Запрос «подробнее» MUST использовать фрагменты прошлого ответа по `chunk_id` из памяти без нового поиска. Ответ LLM MUST проходить проверку опоры: если ответ не пересекается по содержанию с найденными фрагментами, бот SHALL показывать только фрагменты со ссылками. Отказ по-прежнему SHALL быть «В playbook этого нет» с кнопкой [Спросить наставника].

#### Scenario: Уточнение с историей
- **WHEN** стажёр спросил «Что такое Zero Bug Policy?», а затем «а кто за неё отвечает?»
- **THEN** поиск выполняется по запросу, включающему Zero Bug Policy, а ответ содержит ссылку на `development-principles.md`

#### Scenario: Подробнее без нового поиска
- **WHEN** после ответа по playbook стажёр пишет «подробнее»
- **THEN** бот отвечает по тем же `chunk_id` из памяти, и поиск по индексу не вызывается

#### Scenario: Ответ без опоры
- **WHEN** LLM вернула ответ, не пересекающийся с найденными фрагментами
- **THEN** бот показывает найденные фрагменты со ссылками вместо ответа LLM

#### Scenario: Уточнение вне корпуса
- **WHEN** после ответа по playbook стажёр спрашивает «а пароль от Wi-Fi?»
- **THEN** бот отвечает «В playbook этого нет» с кнопкой [Спросить наставника]

### Requirement: FR-H3-08 Составной вопрос
Если вопрос соединяет темы союзом «и», поиск SHALL выполняться по всему вопросу и дополнительно по каждой части отдельно; результаты MUST объединяться без дублей, и в ответ MUST попадать не более 4 фрагментов. Ответ MUST содержать ссылку на раздел по каждой найденной теме. Если найдены два и более раздела одного списка, модель SHALL получать список целиком (до 8 разделов), а бот — показывать его оглавление отдельным блоком ниже.

#### Scenario: Список целиком
- **WHEN** по вопросу «расскажи про ценности и миссию авито» найдены 2 из 5 разделов «Ценность № N»
- **THEN** модель получает все пять ценностей, в ответе ссылки на все пять, оглавление «Ценность № 1–5» показано отдельным блоком

#### Scenario: Составной вопрос
- **WHEN** стажёр пишет «расскажи про ценности и миссию авито»
- **THEN** в ответе используются фрагменты и о миссии, и о ценностях из `mission-and-values.md`, и показаны ссылки на оба раздела

#### Scenario: Не больше четырёх фрагментов
- **WHEN** поиск по частям составного вопроса находит больше 4 подходящих фрагментов из разных разделов
- **THEN** в ответ попадают не более 4 фрагментов без дублей

### Requirement: FR-H3-09 Текст ответа без служебных фраз
Ответ по playbook SHALL быть пересказом для стажёра и MUST NOT упоминать «фрагменты» или «материалы». Если часть вопроса не покрыта найденными разделами, бот SHALL прямо писать «О … в playbook не нашёл», называя эту часть.

#### Scenario: Без служебных фраз
- **WHEN** бот отвечает по playbook
- **THEN** в тексте ответа нет слов «фрагменты» и «материалы»

#### Scenario: Без Markdown-разметки
- **WHEN** модель выделила часть ответа как `**Миссия Авито:**`
- **THEN** стажёр видит выделение жирным (или простой текст), а не звёздочки

#### Scenario: Часть вопроса не покрыта
- **WHEN** стажёр спрашивает о двух темах, а в playbook есть только одна
- **THEN** бот отвечает по найденной теме со ссылкой и пишет «О <второй теме> в playbook не нашёл»
