# brief-storage Specification

## Purpose
Хранение данных утреннего брифа (H0) в backend: состояние доставки и снимок календаря, настройки,
статистика с разграничением по ролям, редирект `/r/<token>` для учёта переходов и внешние координаты
объектов каталога для сборщиков H0 и H1.

## Requirements

### Requirement: ST4-BRIEF-1 Постоянное состояние H0
Backend SHALL хранить настройки, последний доставленный бриф и ID доставленных изменений пользователя. Подтверждение sent и снимок календаря MUST сохраняться атомарно. Повтор подтверждения MUST сохранять первоначальный sent_at и снимок; failed и отсутствие снимка MUST NOT удалять предыдущую базу. Более старый доставленный бриф MUST NOT заменять более новую календарную базу.

#### Scenario: Ошибка отправки или календаря
- **WHEN** отправка не удалась либо следующий доставленный бриф не содержит снимка
- **THEN** сохранённый календарь остаётся прежним

#### Scenario: Повтор и рестарт
- **WHEN** доставка подтверждена повторно и агент перезапущен
- **THEN** время доставки, календарь, ID доставленных изменений и настройки доступны из backend без изменения

### Requirement: ST4-REDIRECT-1 Переход по сохранённому пункту
Backend SHALL создавать криптографически случайный уникальный токен для пункта брифа. GET /r/{token} SHALL после доставки фиксировать один идемпотентный click и первое read_at и перенаправлять на сохранённый HTTP(S) URL. HEAD SHALL NOT создавать события. Черновик, ошибочная отправка и неизвестный токен MUST возвращать 404. URL запроса MUST NOT определять адрес назначения. Ответ MUST запрещать кэширование и передачу Referer.

#### Scenario: Повтор перехода
- **WHEN** ссылка доставленного пункта открыта несколько раз
- **THEN** адрес берётся из БД, read_at неизменен и бриф учитывается прочитанным/с переходом один раз

#### Scenario: Чужой или недоставленный пункт
- **WHEN** передан неизвестный токен или токен черновика
- **THEN** backend отвечает 404 без раскрытия данных

### Requirement: ST4-STATS-1 Статистика по правам
Backend SHALL возвращать счётчики sent/read/clicked/positive/negative только доставленных брифов. Стажёр SHALL видеть себя, наставник своих стажёров, тимлид стажёров своей команды. Каждый бриф MUST учитываться не более одного раза в каждом счётчике.

#### Scenario: Изоляция и повторы
- **WHEN** наставник запрашивает статистику после повторных кликов
- **THEN** ответ содержит только его стажёров и повторный клик не увеличивает число брифов с переходом

### Requirement: ST4-CATALOG-1 Координаты объектов
Каталог SHALL поддерживать необязательный target с внешними ID объекта и ключевыми словами для сборщиков H0/H1. Поля MUST соответствовать инструменту; credentials и неизвестные поля MUST отклоняться атомарно с seed. Агент MUST брать target из авторизованного каталога конкретного пользователя, без общего кэша по object_id между командами.

#### Scenario: Секрет в координатах
- **WHEN** seed содержит target.token
- **THEN** импорт целиком отклонён с безопасной ошибкой поля
