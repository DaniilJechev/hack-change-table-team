# team-card-upload Specification

## Purpose
Загрузка синтетической карточки своей команды, типизированная валидация, версии и сохранение stage для H2.

## Requirements

### Requirement: ST3-CARD-1 Загрузка карточки своей команды
Backend SHALL принимать YAML текущего seed-формата через POST /api/v1/team-card
с заголовками X-Buddy-Key и X-Buddy-User. Загружать карточку MUST только наставник
или тимлид своей команды. Карточка MUST содержать synthetic=true, team_id, name;
люди MUST содержать user_id, name, role, areas и contact_url.
Неизвестные поля, неверные типы, некорректные ссылки и ссылки на чужих участников
MUST отклоняться с безопасными русскими ошибками с путями полей.

#### Scenario: Новая версия
- **WHEN** наставник или тимлид загружает валидную изменённую карточку своей команды
- **THEN** backend атомарно создаёт версию; предыдущая версия остаётся доступна по source_path

#### Scenario: Повтор загрузки
- **WHEN** повторена текущая карточка без изменений
- **THEN** backend возвращает текущую версию без дубликата

#### Scenario: Невалидная карточка
- **WHEN** в people[2] отсутствует role или YAML не соответствует схеме
- **THEN** backend возвращает 400 со списком ошибок с путями полей без создания версии

#### Scenario: Недостаточно прав
- **WHEN** карточку загружает стажёр или указан team_id чужой команды
- **THEN** backend возвращает 403 без изменения данных

### Requirement: ST3-CARD-2 Метаданные этапа проекта
Карточка SHALL сохранять опциональный stage с epic_key и source_url, совместимый с H2 Q5; неверные или неизвестные поля внутри stage MUST отклоняться безопасной ошибкой.

#### Scenario: Карточка агента с эпиком
- **WHEN** загружается seed-карточка demo-orders со stage.epic_key=ORD-100
- **THEN** поле сохраняется и карточка принимается тем же загрузчиком, что используется REST
