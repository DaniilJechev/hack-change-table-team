# h0-brief Specification

## Purpose
Утренний обход и бриф (H0): каждое утро стажёр получает в Telegram одно сообщение с изменениями
в Google Calendar, Git (GitHub) и Jira и одно главное действие на день. У каждого пункта есть ссылка на объект.
Главная метрика — доля прочитанных брифов ≥ 60 %.

## Requirements

### Requirement: FR-H0-01 Сбор изменений из трёх источников
Система SHALL собирать изменения стажёра из Google Calendar, Git и Jira с момента последнего успешно отправленного брифа; для Google Calendar изменения MUST определяться сравнением с сохранённым снимком событий.

#### Scenario: Изменения в Git и Jira
- **WHEN** с прошлого брифа Анна запросила изменения в PR #45, а Олег упомянул Даниила в ORD-118
- **THEN** сборщики возвращают оба изменения с типами `pr_changes_requested` и `jira_mention`

#### Scenario: Перенос встречи
- **WHEN** в текущем снимке календаря синк по ORD-101 начинается в 12:00, а в сохранённом — в 15:00
- **THEN** сборщик календаря возвращает изменение «перенос» с полями `before=15:00` и `after=12:00`

#### Scenario: Отмена встречи
- **WHEN** событие есть в сохранённом снимке, но отсутствует в текущем
- **THEN** сборщик календаря возвращает изменение «отмена»

#### Scenario: Прошлый бриф не отправился
- **WHEN** вчерашний бриф завершился ошибкой отправки
- **THEN** изменения собираются с момента последнего успешно отправленного брифа

### Requirement: FR-H0-02 Нормализация пунктов
Каждое изменение SHALL приводиться к структуре `BriefItem {id, source, type, title, url, priority_class, related_task, before, after, created_at}`.

#### Scenario: Пункт из Jira
- **WHEN** сборщик Jira получил упоминание в ORD-118
- **THEN** создаётся `BriefItem` с `source=jira`, `priority_class=people` и `url` на комментарий ORD-118

### Requirement: FR-H0-03 Ранжирование и лимит
Пункты SHALL сортироваться по классам «блокер → запрос людей → дедлайн → информация»; в бриф MUST попадать не более 5 пунктов, остальные — под кнопку «Ещё N».

#### Scenario: Семь изменений
- **WHEN** собрано 7 изменений, из них 2 блокера
- **THEN** бриф содержит 5 пунктов, первыми идут 2 блокера, и есть кнопка «Ещё 2»

### Requirement: FR-H0-04 Главное действие
Главное действие на день SHALL выбираться правилом — первый пункт, требующий действия стажёра; LLM MUST только формулировать его текст.

#### Scenario: Блокер в Git
- **WHEN** первый по приоритету пункт — запрошенные изменения в PR #45
- **THEN** строка «▶ Главное сегодня» относится к PR #45

### Requirement: FR-H0-LINK-1 Ссылка на конкретный объект
Каждый пункт брифа MUST содержать ссылку на конкретный объект: событие календаря, PR или комментарий, задачу или комментарий.

#### Scenario: Пункт про комментарий
- **WHEN** в брифе есть пункт о комментарии Анны в PR #45
- **THEN** кнопка [Открыть] ведёт на этот комментарий, а не на список PR

### Requirement: FR-H0-LINK-2 Пункт без ссылки не показывается
Пункт без валидной ссылки SHALL NOT попадать в бриф; проверку MUST выполнять код.

#### Scenario: Пустой URL
- **WHEN** сборщик вернул изменение без URL
- **THEN** пункт исключается из брифа и записывается в журнал ошибок

### Requirement: FR-H0-LINK-3 LLM не меняет ссылки
LLM SHALL получать только `item_id` и текст пунктов; URL MUST подставляться кодом по `item_id`.

#### Scenario: LLM вернула неизвестный item_id
- **WHEN** в ответе LLM есть строка с `item_id`, которого нет среди отобранных пунктов
- **THEN** строка отбрасывается; если отброшено больше половины строк, бриф строится по шаблону

### Requirement: FR-H0-05 Недоступный источник
При ошибке источника бриф SHALL отправляться без его блока с пометкой о недоступности.

#### Scenario: Jira не отвечает
- **WHEN** mcp-atlassian вернул ошибку
- **THEN** бриф содержит пункты Calendar и Git и строку «Данные из Jira сейчас недоступны»

### Requirement: FR-H0-06 Расписание
Бриф SHALL отправляться за 30 минут до первого стендапа в календаре стажёра, а при отсутствии стендапа — в 09:30; в выходные и дни отсутствия бриф MUST NOT отправляться.

#### Scenario: Стендап в 10:00
- **WHEN** в календаре Даниила стендап в 10:00
- **THEN** бриф отправляется в 09:30

#### Scenario: Суббота
- **WHEN** наступает суббота
- **THEN** бриф не отправляется

### Requirement: FR-H0-07 Бриф по запросу
Команда `/brief` и фразы вроде «что нового?» SHALL формировать бриф немедленно; если назван один источник — только по нему.

#### Scenario: Вопрос про PR
- **WHEN** стажёр пишет «Есть что по PR?»
- **THEN** бот отвечает только пунктами из Git

#### Scenario: Изменений нет
- **WHEN** с прошлого брифа изменений нет
- **THEN** бот отвечает «Изменений нет» и называет ближайшую встречу или дедлайн со ссылкой

### Requirement: FR-H0-08 Статус «прочитан» и метрики
Система SHALL отмечать бриф прочитанным при первом сигнале стажёра — нажатии [✅ Прочитал], открытии остальных пунктов кнопкой «Ещё N», переходе по ссылке через редирект `/r/<token>`, реакции 👍/👎 или ответе на сообщение брифа; `/stats` MUST показывать долю прочитанных брифов и долю брифов с переходами. Для сохранённого в backend брифа при заданном REDIRECT_BASE_URL ссылки MUST использовать выданные backend случайные токены, отдельные от стабильного item_id изменения. В офлайн-демо SeedData, без сохранённого токена или без REDIRECT_BASE_URL ссылка MUST вести прямо на объект.

#### Scenario: Переход по ссылке
- **WHEN** стажёр нажимает [Открыть] у пункта брифа
- **THEN** редирект фиксирует переход, бриф получает read_at, и стажёр попадает на объект

#### Scenario: Нет реакции
- **WHEN** до следующего брифа стажёр не взаимодействовал с текущим
- **THEN** бриф остаётся непрочитанным в метриках

#### Scenario: Ответ на бриф
- **WHEN** стажёр отвечает текстом на сообщение брифа
- **THEN** бриф получает read_at

#### Scenario: Офлайн-демо
- **WHEN** SeedData формирует бриф без backend
- **THEN** ссылки остаются прямыми даже при заданном REDIRECT_BASE_URL, а сигналы кнопок сохраняются в демо-сессии

### Requirement: FR-H0-09 Настройки брифа
Команда `/settings` SHOULD позволять менять время брифа и включать тихий режим (без сообщения в день без изменений).

#### Scenario: Тихий режим
- **WHEN** тихий режим включён и изменений нет
- **THEN** бриф в этот день не отправляется

### Requirement: FR-H0-10 Изменение показывается один раз
Пункт, уже попавший в успешно отправленный бриф, SHALL NOT показываться повторно; идентификатор пункта MUST быть стабильным для одного и того же изменения.

#### Scenario: Повторный запрос
- **WHEN** стажёр получил бриф и сразу пишет «Что нового?»
- **THEN** бот отвечает «Изменений нет» и называет ближайшую встречу или дедлайн со ссылкой

### Requirement: FR-H0-11 Отправленным считается только доставленный бриф
Бриф SHALL получать статус `sent` только после того, как Telegram принял сообщение; при ошибке отправки бриф MUST получать статус `failed`, а снимок календаря и отметка последнего брифа MUST NOT меняться.

#### Scenario: Telegram отклонил сообщение
- **WHEN** отправка брифа завершилась ошибкой
- **THEN** бриф получает статус `failed`, и следующий бриф снова содержит те же изменения

#### Scenario: Бриф не удалось сохранить
- **WHEN** backend не принял черновик брифа
- **THEN** бот всё равно показывает пункты со ссылками, но без кнопок [✅ Прочитал] и оценки
