# Агентный цикл: LLM отвечает по результатам инструментов

## Зачем
На живом прогоне бот отвечает шаблонно. LLM только классифицирует текст (Router) и переписывает
строки брифа и ответ H3; 12 из 16 кейсов отвечают шаблонами, LLM не видит диалога, составной
вопрос сводится к одному кейсу, всё вне кейсов уходит в `clarify`/`out_of_scope`.

## Что меняется
- Новый узел графа `agent`: LLM (`LLM_MODEL`, целевая — `deepseek/deepseek-v4.1-flash-1017`)
  получает историю диалога и инструменты — существующие кейсы Executors — и сама пишет ответ.
  До 3 шагов, до 4 вызовов инструментов, до 20 с на ход.
- Факты помечаются метками `[S#]` источников из результатов инструментов; ссылки подставляет
  код (жёсткое правило 2). Ответ с URL, неизвестной меткой или фактами без меток отклоняется.
- Запасной вариант без LLM (жёсткое правило 3): результат вызванного инструмента или нынешний
  путь Router → Executor.
- Быстрый путь без LLM остаётся: команды, кнопки, планировщик, правила уточнений, отказ по
  персональным данным.
- `AGENT_MODE=agent|router`, по умолчанию `agent`; без настоящей LLM (демо без
  `LLM_IN_DEMO`, `LLM_PROVIDER=fake`) работает нынешний путь.
- Память хранит текст реплики пользователя и проверенный ответ бота (секреты вырезаются,
  до 600 символов, окно и TTL прежние) — меняется FR-MEM-04.
- `evals/agent/`: набор кейсов и скрипт сравнения моделей (прогон на реальной LLM — вручную).

## Затрагивает
`agent/` (llm, graph, новый `agent/buddy/agent/`, memory, config, service), `.env.example`,
`evals/agent/`. Корпоративные сервисы — только чтение: инструменты агента — те же Executors с
теми же белыми списками MCP. Демо-режим работает на фикстурах.

## Зависимости
FR-MEM-04 определён в активном изменении `stage-4-langgraph-memory`; его нужно архивировать
раньше этого. Изменение требований согласовать с Даниилом.
