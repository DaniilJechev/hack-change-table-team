# Агентный цикл: LLM отвечает по результатам инструментов

## Зачем
На живом прогоне бот отвечает шаблонно. LLM только классифицирует текст (Router) и переписывает
строки брифа и ответ H3; 12 из 16 кейсов отвечают шаблонами, LLM не видит диалога, составной
вопрос сводится к одному кейсу, всё вне кейсов уходит в `clarify`/`out_of_scope`.

## Что меняется
- Новый узел графа `agent`: LLM (`LLM_MODEL`, целевая — `deepseek/deepseek-v4.1-flash-1017`)
  получает историю диалога и инструменты — существующие кейсы Executors — и сама пишет ответ.
  До 3 шагов, до 4 вызовов инструментов, до 20 с на ход.
- Факты помечаются метками `[S#]` источников из результатов инструментов; ссылки подставляет
  код (жёсткое правило 2). Ответ с URL, неизвестной меткой или фактами без меток отклоняется.
- Запасной вариант без LLM (жёсткое правило 3): результат вызванного инструмента или нынешний
  путь Router → Executor.
- Быстрый путь без LLM остаётся: команды, кнопки, планировщик, правила уточнений, отказ по
  персональным данным.
- `AGENT_MODE=agent|router`, по умолчанию `agent`; без настоящей LLM (демо без
  `LLM_IN_DEMO`, `LLM_PROVIDER=fake`) работает нынешний путь.
- Память хранит текст реплики пользователя и проверенный ответ бота (секреты вырезаются,
  до 600 символов, окно и TTL прежние) — меняется FR-MEM-04.
- `evals/agent/`: набор кейсов и скрипт сравнения моделей (прогон на реальной LLM — вручную).

## Затрагивает
`agent/` (llm, graph, новый `agent/buddy/agent/`, memory, config, service), `.env.example`,
`evals/agent/`. Корпоративные сервисы — только чтение: инструменты агента — те же Executors с
теми же белыми списками MCP. Демо-режим работает на фикстурах.

## Зависимости
FR-MEM-04 и FR-MEM-05 определены в активном изменении `stage-4-langgraph-memory`; его нужно
архивировать раньше этого, иначе `openspec archive agent-orchestrator` откажет: MODIFIED требует
существующей спецификации `context-memory`.

## Что согласовать с Даниилом (и с Ильёй по п. 6)

### 1. FR-MEM-04: в памяти хранятся реплики
- **Было:** в память не пишутся сырые ответы LLM; ход хранит только кейс, параметры, сущности и
  краткий итог до 200 символов. В LLM память уходит только JSON-сводкой для Router.
- **Стало:** ход дополнительно хранит текст пользователя и показанный ответ бота (после всех
  проверок кода), до 600 символов каждый, секреты вырезаются. Агент получает их как реплики
  диалога. Окно (6 ходов), TTL (30 мин), изоляция по `user_id` + `team_id` и Redis в живом режиме
  не меняются; сводка для Router по-прежнему без текстов.
- **Решить:**
  - а) допустимо ли держать сырой текст переписки в Redis 30 минут;
  - б) допустимо ли отправлять историю внешнему провайдеру LLM (OpenRouter → DeepSeek; в запросе
    `data_collection: deny`);
  - в) лимит 600 символов на реплику;
  - г) **история — не источник фактов** (см. `reports/BUG_AGENT_ANSWERS_FROM_HISTORY.md`):
    предлагаем записать в FR-MEM-04, что факты из прошлых ответов MUST NOT выдаваться как
    актуальные без вызова инструмента в этом ходу;
    **реализовано, ждёт согласования:** промпт `SYSTEM` + FR-AG-09 (без инструментов в ходе ключ задачи или номер PR в ответе → запасной вариант), сценарий «Факт из истории без инструментов»;
    **реализовано 13.11, согласование пропущено по решению Эмиля:** имя человека из карточки или статус доступа без инструмента → один повтор с обязательным инструментом команды или доступов (FR-AG-05, FR-AG-09);
  - д) память привязана к профилю, а не к треду Studio или чату: так и оставить?

### 2. FR-MEM-05 противоречит FR-AG-11 — нужна дельта
- **FR-MEM-05 сейчас:** короткие продолжения («ещё», «а по Jira?», «второй пункт») SHALL
  распознаваться правилами **без LLM**; «Ну и как?» без памяти → Router → `clarify`.
- **FR-AG-11:** при включённом агенте уточнение сначала обрабатывает агент по истории, правила —
  только если агент не ответил.
- **Решить:** принять FR-AG-11 и добавить в это изменение MODIFIED FR-MEM-05 («правила — запасной
  вариант при включённом агенте; при `AGENT_MODE=router` — как прежде») или вернуть правила первыми.

### 3. Требования Router (RT-*) описывают только запасной путь
При `AGENT_MODE=agent` Router вызывается лишь при отказе агента, для `/команд` и длинных текстов.
Сценарии RT-03 («доступ к Анне» → `clarify` с вариантами от кода), RT-09 (границы кейсов) и
меню `clarify` в обычном диалоге больше не срабатывают — их заменяет ответ агента.
**Решить:** считать RT-* требованиями запасного пути и дописать это в спецификацию `router`.

### 4. `AGENT_MODE=agent` по умолчанию
- Включается везде, где настоящая LLM: живой режим и демо с `LLM_IN_DEMO=true`. Демо без
  `LLM_IN_DEMO` и `LLM_PROVIDER=fake` работают как раньше.
- Цена и скорость по `evals/agent/report.json` (DeepSeek V4.1 Flash): около $0.0002 за ход, в
  среднем 3–4 с, p95 около 6 с, бриф через агента около 10 с (было 1–3 с).
- В `.env.example` модель по умолчанию — `deepseek/deepseek-v4.1-flash-1017`.
- **Решить:** `agent` по умолчанию сразу или `router` до пилота на живых стажёрах.

### 5. Последствия для H0 и H3
- **H0:** бриф, который агент пересказал, отмечается доставленным (`brief_id`), и метка «с
  последнего брифа» (FR-H0-01) сдвигается, даже если в пересказ попали не все пункты.
  **Решить:** допустимо или для пересказа не отмечать доставку.
- **H3:** агент пересказывает ответ playbook своими словами; проверка опоры на фрагменты
  (`grounded`, FR-H3-07) применяется к ответу исполнителя, но не к пересказу агента, а пометка
  «Playbook может быть устаревшим» может выпасть. **Решить:** добавлять пометку кодом к ответу
  агента, если вызывался `playbook_qa`.
