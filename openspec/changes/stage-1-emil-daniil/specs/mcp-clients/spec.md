## ADDED Requirements

### Requirement: ST1-MCP-1 Подключение и discovery
MCP-клиент SHALL поддерживать stdio и Streamable HTTP через официальный Python SDK, выполнять initialize и пагинированный tools/list, сохранять имена, входные схемы и происхождение discovery. Отсутствие нужного инструмента MUST давать диагностический статус, а не выдуманное имя.

#### Scenario: Четыре сервера
- **WHEN** запускается диагностика четырёх настроенных серверов
- **THEN** для каждого независимо возвращается результат tools/list или понятный статус недоступности

#### Scenario: Нет нужного инструмента
- **WHEN** сервер не публикует необходимый инструмент
- **THEN** вызов отклоняется до обращения к tools/call

### Requirement: ST1-RO-1 Запрет инструментов записи
Клиент MUST вызывать только явно разрешённые инструменты текущего кейса, обнаруженные на сервере, и валидировать аргументы по входной JSON Schema. Аннотация readOnlyHint сама по себе SHALL NOT разрешать инструмент. Имя вне белого списка или явная аннотация записи MUST блокироваться. Исход вызова SHALL попадать в журнал без токенов и содержимого ответов.

#### Scenario: Неизвестный или пишущий инструмент
- **WHEN** запрошен инструмент вне белого списка или с readOnlyHint=false
- **THEN** запрос не отправляется серверу и фиксируется отказ

#### Scenario: Неверные аргументы
- **WHEN** параметры не соответствуют опубликованной схеме
- **THEN** tools/call не выполняется

### Requirement: ST1-FIX-1 Запись и offline replay
RECORD_MODE SHALL сохранять успешные ответы по ключу server/tool/канонический JSON аргументов и шагу сценария, вместе с discovery, происхождением и статусом synthetic/recorded. DEMO_MODE MUST читать только фикстуры и не создавать сетевых сессий. Одновременные RECORD_MODE и DEMO_MODE MUST отклоняться. Ошибки MCP и секреты MUST NOT сохраняться в фикстурах.

#### Scenario: Запись и повтор
- **WHEN** выполнен успешный разрешённый вызов в режиме записи
- **THEN** тот же вызов в offline режиме возвращает сохранённый ответ независимо от порядка ключей аргументов

#### Scenario: Нет фикстуры
- **WHEN** нет записи для точных аргументов и шага
- **THEN** возвращается явная ошибка отсутствия данных без live fallback

#### Scenario: Ошибка или секрет в ответе
- **WHEN** MCP вернул isError или ответ содержит значение настроенного секрета
- **THEN** ответ не записывается

### Requirement: ST1-AUTH-1 Авторизация Miro
Клиент SHALL поддерживать OAuth 2.1 через SDK для Miro и хранить секретное состояние только в локальном .env. В отчёте MUST различаться подготовленный auth flow и успешно завершённая авторизация.

#### Scenario: Нет авторизации
- **WHEN** Miro требует вход, а учётные данные ещё не получены
- **THEN** диагностика сообщает о необходимости авторизации и не объявляет сервер проверенным

### Requirement: ST1-DATA-1 Согласованные тестовые данные
Набор «день стажёра» MUST быть синтетическим, иметь согласованные ID объектов пяти сервисов, ссылки на источники и явный статус готовности реальных объектов. Успех fake-сервера SHALL NOT выдаваться за проверку официального MCP.

#### Scenario: Offline сценарий
- **WHEN** проверяется синтетический набор без аккаунтов
- **THEN** все ID согласованы, нет реальных персональных данных и сценарий помечен synthetic
