# Этап 4: движок агента на LangGraph и контекстная память диалога

## Why
Этап 4 roadmap закрыт по H0 и H3, но каждый запрос стажёра обрабатывается без контекста: уточнения «а по Jira?», «подробнее про 2-й пункт», «ещё» уходят в `clarify` или в чужой кейс. Сравнение моделей (`reports/LLM_MODEL_COMPARISON.md`) показало, что ошибки Router общие для моделей и лечатся промптом и нормализацией в коде. Нужен явный, тестируемый граф обработки запроса, в который память встраивается отдельными узлами, без перехода к агенту со свободным выбором инструментов.

## What Changes
- Движок агента — детерминированный `StateGraph` LangGraph: `load_memory → resolve_followup → route → <executor> → guard → save_memory`. Узлы-исполнители по семействам кейсов: `brief`, `playbook`, `team`, `access`, `template`. LLM вызывается только внутри узлов, рёбра выбирает код; белые списки инструментов кейсов и запасные варианты без LLM не меняются.
- Флаг `AGENT_ENGINE=legacy|graph`. Оба движка обязаны давать одинаковые ответы на текущих тестах, evals Router и демо-сценарии; значение по умолчанию переключается на `graph` только после подтверждения паритета.
- Новая возможность `context-memory` (FR-MEM-01…06): окно последних 6 ходов с кейсом, параметрами и разрешёнными сущностями, TTL 30 минут, изоляция по `user_id` + `team_id`, `/reset`, разрешение уточнений правилами и (опционально) LLM со схемой, хранение в памяти процесса в демо и тестах и через REST backend в живом режиме.
- H0: FR-H0-12 — уточнения по брифу из памяти, ссылки только из кода.
- H3: FR-H3-07 — переформулировка уточнений с учётом истории, «подробнее» по `chunk_id` без нового поиска, проверка опоры ответа на фрагменты.
- Router: доверенная сводка памяти как JSON-данные (RT-08), границы кейсов и нормализация параметров в коде (RT-09).
- Зависимость `langgraph>=1.0,<2` в `agent/`; новый набор evals `evals/memory/cases.jsonl`.

## Impact
`agent/` (движок, память, Router, H0, H3, промпты), `evals/`, OpenSpec, отчёт этапа. В живом режиме память хранится через REST backend — эндпоинты памяти согласуются с Ильёй отдельным изменением в зоне `backend/`; до этого живой режим использует хранилище процесса с тем же TTL. Корпоративные сервисы — только чтение; агент записывает только наши данные через REST backend (жёсткое правило 1). `DEMO_MODE=true` работает на in-memory checkpointer/store без внешних аккаунтов. Бот не запускается без отдельного поручения.

Согласование с активным изменением `stage-four-backend`: постоянное состояние брифа (черновик, снимок календаря, последний доставленный бриф, настройки, статистика) и редирект по токенам уже описаны там (ST4-BRIEF-1, ST4-REDIRECT-1, FR-H0-08), поэтому здесь FR-H0-08 и FR-H0-11 не меняются, чтобы не создавать конфликтующих дельт.
