## ADDED Requirements

### Requirement: FR-H4-01 Текст по слайдам
Агент SHALL принимать презентацию в PDF или PPTX и извлекать список слайдов: номер (с 1),
заголовок и полный текст. Формат определяется по расширению и сигнатуре файла.
PDF читается библиотекой pypdf внутри агента; заголовок — первая непустая строка страницы.
PPTX читается через MCP-сервер PowerPoint (Office-PowerPoint-MCP-Server 2.0.7) только
инструментами `open_presentation` и `extract_presentation_text`; остальные инструменты
upstream MUST удаляться обёрткой до запуска, сервер MUST открывать только файлы из своей
папки загрузок. Заголовок PPTX — заголовок слайда из ответа сервера.
Файл MUST NOT изменяться и не пересылаться в LLM для обязательных проверок. Файл больше
10 МиБ или 30 слайдов, другого формата, битый или без текстового слоя SHALL отклоняться
понятным сообщением без проверки.

#### Scenario: Обычная презентация
- **WHEN** стажёр присылает презентацию из 8 слайдов с текстом в PDF или PPTX
- **THEN** агент получает 8 слайдов с номерами 1–8, заголовками и текстом

#### Scenario: PPTX только через MCP для чтения
- **WHEN** обёртка PowerPoint-MCP запускается
- **THEN** в tools/list ровно два инструмента; путь вне папки загрузок отклоняется

#### Scenario: PPTX в демо
- **WHEN** DEMO_MODE=true и прислан учебный PPTX
- **THEN** текст берётся из записанных фикстур сервера

#### Scenario: Свой PPTX в демо
- **WHEN** DEMO_MODE=true, для PPTX нет фикстуры и задан PPTX_MCP_URL локального контейнера PowerPoint-MCP
- **THEN** агент читает файл этим контейнером (корпоративный аккаунт не нужен); если контейнер не задан или недоступен, бот просит PDF

#### Scenario: Другой формат
- **WHEN** стажёр присылает .docx
- **THEN** бот просит PDF или PPTX и не запускает проверку

#### Scenario: Скан без текста
- **WHEN** в файле нет извлекаемого текста ни на одном слайде
- **THEN** бот просит прислать файл с текстовым слоем и не выдаёт отчёт проверки

### Requirement: FR-H4-02 Обязательный критерий «Структура»
Агент SHALL считать критерий пройденным, если в презентации найдены все шесть разделов
учебной структуры. Сравнение MUST выполняться кодом без LLM по нормализованному заголовку
слайда: нижний регистр, «ё» → «е», без нумерации («1.», «2)»), эмодзи и знаков препинания
по краям. Раздел найден, если заголовок совпадает с синонимом или начинается с него;
при нескольких совпадениях побеждает самый длинный синоним. Порядок разделов не проверяется.
Раздел может занимать несколько слайдов.

Словарь (синтетический, не регламент Авито):

| № | Раздел | Синонимы заголовка |
|---|---|---|
| 1 | Титул | особое правило, см. ниже |
| 2 | Цели стажировки | цели стажировки; цели; мои цели; цели на стажировку; ожидания от стажировки |
| 3 | Выполненные задачи | выполненные задачи; что сделано; что я сделал; сделанные задачи; проделанная работа; мои задачи |
| 4 | Результаты | результаты; итоги; что изменилось; эффект для команды; результаты в цифрах |
| 5 | Сложности и чему научился | сложности и чему научился; сложности; трудности; чему научился; чему я научился; уроки |
| 6 | Планы до конца стажировки | планы до конца стажировки; планы; дальнейшие планы; следующие шаги; что дальше |

Титул: слайд 1 SHALL считаться титулом, если его текст содержит не меньше трёх из четырёх
признаков — «наставник»; «команда»; «стажер» или «стажировка»; период (две даты, два месяца
или диапазон вида «сентябрь – ноябрь 2026»). Заголовок «титул» не требуется.

#### Scenario: Все шесть разделов
- **WHEN** титул на слайде 1, а заголовки «Цели», «Что сделано», «Итоги», «Трудности», «Что дальше» — на слайдах 2–6
- **THEN** критерий «Структура» ✅, у каждого раздела указан номер слайда

#### Scenario: Нет раздела
- **WHEN** в презентации нет слайда с заголовком из синонимов раздела «Результаты»
- **THEN** критерий ❌ с замечанием «нет раздела „Результаты“» и перечнем допустимых заголовков

#### Scenario: Нумерация и регистр
- **WHEN** заголовок слайда «3. ВЫПОЛНЕННЫЕ ЗАДАЧИ:»
- **THEN** слайд относится к разделу «Выполненные задачи»

#### Scenario: Неполный титул
- **WHEN** на слайде 1 есть только имя и команда без наставника и периода
- **THEN** раздел «Титул» не найден, замечание называет недостающие признаки

### Requirement: FR-H4-03 Обязательный критерий «Факты»
Агент SHALL находить на слайдах ключи задач вида `[A-Z][A-Z0-9]+-\d+` и для каждого
уникального ключа вызывать только `jira_get_issue` (кейс `equator_check`, только чтение).
Статус на слайде определяется по словам в той же строке, что и ключ:

| Группа | Слова на слайде | Статусы Jira |
|---|---|---|
| Готово | готово; сделано; выполнено; закрыта; done | Done; Closed; Resolved |
| В работе | в работе; в процессе; делаю; in progress | In Progress |
| На ревью | на ревью; на проверке; review | In Review; Code Review |
| В планах | в планах; запланировано; to do; todo | To Do; Open; Backlog |

Задача без слов статуса проверяется только на существование. Результат по ключу:
✅ задача есть и группа статуса совпадает; ⚠️ задача есть, но группа другая (показать оба
статуса); ❌ задача не найдена — Jira ответила ошибкой инструмента по этому ключу, а в демо
для ключа нет фикстуры (синтетическая Jira состоит из фикстур). Недоступность Jira
(транспорт, авторизация, конфигурация) MUST NOT выдаваться за «задачи нет»: критерий
получает статус «не проверено». Критерий пройден, если все ключи ✅ и найден хотя бы один
ключ. Ссылки на задачи MUST подставляться кодом из ответа Jira.

#### Scenario: Совпадение статуса
- **WHEN** на слайде 3 строка «ORD-118 — в работе», а в Jira ORD-118 In Progress
- **THEN** ✅ ORD-118, слайд 3, ссылка на задачу

#### Scenario: Статус расходится
- **WHEN** на слайде строка «ORD-121 — готово», а в Jira ORD-121 To Do
- **THEN** ⚠️ ORD-121 с текстом «на слайде: готово, в Jira: To Do», критерий не пройден

#### Scenario: Несуществующая задача
- **WHEN** на слайде ключ ORD-999, а Jira отвечает, что задачи нет
- **THEN** ❌ ORD-999 с номером слайда, критерий не пройден

#### Scenario: Jira недоступна
- **WHEN** вызов jira_get_issue завершается ошибкой транспорта
- **THEN** критерий «не проверено», кнопка [Отправить наставнику] не показывается

### Requirement: FR-H4-04 Отчёт и отправка наставнику
Бот SHALL отвечать списком по критериям ✅ / ⚠️ / ❌ с номерами слайдов, без LLM, по шаблону.
Если «Структура» и «Факты» пройдены, бот SHALL написать «готово к показу наставнику» и показать
[Отправить наставнику]. По нажатию агент MUST вызвать
`mark_progress(user_id, "equator_presentation")` и показать сохранённый статус этапа.
Повторное нажатие MUST NOT менять первое время завершения. Иначе кнопка не показывается.

#### Scenario: Плохая презентация
- **WHEN** в презентации нет двух разделов и один ключ с неверным статусом
- **THEN** отчёт содержит ❌ по разделам и ⚠️ по ключу с номерами слайдов, кнопки нет, трекер не меняется

#### Scenario: Хорошая презентация
- **WHEN** оба обязательных критерия пройдены и стажёр нажимает [Отправить наставнику]
- **THEN** пункт equator_presentation отмечен в имитации трекера, бот показывает статус этапа

#### Scenario: Демо без внешних сервисов
- **WHEN** DEMO_MODE=true и стажёр присылает учебную хорошую презентацию
- **THEN** проверка идёт по фикстурам Jira, отметка — через SeedData, без HTTP к backend
