## ADDED Requirements

### Requirement: FR-TR-01 Отправка трейса хода
После каждого хода графа (текст, кнопка, планировщик) агент SHALL отправлять `turn` (FR-AG-15) в backend
`POST /api/v1/agent-traces` с ключом сервиса, если заданы `BACKEND_URL` и `BUDDY_SERVICE_KEY`, в том числе
в демо-режиме. Отправка MUST идти в фоне и не задерживать ответ; ошибка отправки MUST записываться в лог
только видом ошибки, без текста хода, и MUST NOT менять ответ пользователю.

#### Scenario: Backend недоступен
- **WHEN** backend не отвечает на запись трейса
- **THEN** пользователь получает ответ, а в логе одна строка с видом ошибки

#### Scenario: Ход записан
- **WHEN** стажёр задал вопрос и backend доступен
- **THEN** в `agent_traces` появляется строка с его `user_id`, `team_id`, путём и `turn`

### Requirement: FR-TR-02 Хранение трейсов
Backend SHALL хранить трейсы в таблице `agent_traces` (миграция goose): идентификатор, время сервера,
`user_id`, `team_id`, роль, признак демо, путь, признак запасного пути, кейс, длительность, число обращений
к LLM и вызовов инструментов и `turn` как `jsonb`. Повтор записи с тем же идентификатором MUST NOT создавать
дубль. Тело больше 256 КиБ или с неизвестными полями MUST отклоняться с 400.

#### Scenario: Повтор отправки
- **WHEN** агент дважды отправил трейс с одним идентификатором
- **THEN** в таблице одна строка

#### Scenario: Слишком большой трейс
- **WHEN** тело запроса больше 256 КиБ
- **THEN** backend отвечает 400 и ничего не сохраняет

### Requirement: FR-TR-03 Срок хранения
Backend SHALL удалять трейсы старше `AGENT_TRACE_RETENTION_DAYS` суток (по умолчанию 30) при записи нового
трейса. Значение меньше 1 MUST отклоняться при запуске.

#### Scenario: Старый трейс
- **WHEN** записан новый трейс, а в таблице есть трейс старше срока хранения
- **THEN** старый трейс удалён

### Requirement: FR-TR-04 Доступ к трейсам
Чтение трейсов (`GET /api/v1/agent-traces` — список последних без `turn`, фильтр по `user_id`, до 200 строк;
`GET /api/v1/agent-traces/{id}` — полный трейс) SHALL требовать ключ сервиса и MUST NOT быть доступно по
пользователю или через `buddy-mcp`. Роль метрик Grafana MUST NOT читать таблицу `agent_traces`.

#### Scenario: Без ключа сервиса
- **WHEN** запрос к трейсам пришёл без верного `X-Buddy-Key`
- **THEN** backend отвечает 401

#### Scenario: Полный трейс по идентификатору
- **WHEN** запрошен существующий трейс по идентификатору
- **THEN** ответ содержит поля строки и `turn` без изменений

### Requirement: FR-TR-05 Агрегаты для Grafana
Backend SHALL предоставлять view `metrics_agent` по дням и путям: число ходов, доля запасного пути, средняя
и p95 длительность, среднее число вызовов инструментов. View MUST NOT содержать текст, `user_id` и `turn`;
роль метрик SHALL читать его наравне с остальными `metrics_*`.

#### Scenario: Агрегат без текста
- **WHEN** Grafana читает `metrics_agent`
- **THEN** строки содержат только день, путь и числа
