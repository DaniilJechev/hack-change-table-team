# Этап 1: данные входа и запуск готовых MCP

## Why
Этап 0 объединён в main. Для работы агента нужны пользователи в PostgreSQL,
безопасная REST-привязка по одноразовому приглашению и воспроизводимый запуск
готовых серверов GitHub, Jira и Calendar с доступом только на чтение.

## What Changes
- Миграции goose, пользователи и команды, идемпотентный импорт существующего seed.
- Приглашения с ограниченным сроком: в БД хранится только SHA-256 кода;
  погашение и привязка Telegram выполняются одной транзакцией.
- Служебный REST-контракт входа и определения пользователя для Эмиля.
- Опциональный Compose для Jira/Calendar, GitHub stdio в образе агента,
  закреплённые версии и проверка tools/list без корпоративных аккаунтов.
- Интеграционные проверки PostgreSQL в CI; действующий health и Python-бот сохраняются.

## Impact
Затронуты backend, infra, Compose, CI и техническая инструкция mcp.
Реализация /start в Telegram, MCP-клиенты агента и OAuth Miro остаются у Эмиля.
Реальные вызовы корпоративных API не считаются проверенными без тестовых аккаунтов.
Продуктовые требования platform не изменяются; новая спецификация уточняет их
серверный контракт в рамках порученного Этапа 1.
