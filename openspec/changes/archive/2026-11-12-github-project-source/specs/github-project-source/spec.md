## ADDED Requirements

### Requirement: GH-SOURCE-1 Живой репозиторий команды
Backend SHALL принимать GITHUB_REPOSITORY (owner/repo), GITHUB_TEAM_ID,
GITHUB_CATALOG_OBJECT_ID и GITHUB_USER_LOGINS (JSON user_id → GitHub login).
Конфигурация SHALL применяться только к указанной команде и разрешённому GitHub-объекту
каталога. Роли, запреты и Telegram-привязки MUST сохраняться. Некорректная конфигурация
MUST отклоняться при старте без вывода значений. Синтетические seed и фикстуры MUST NOT
меняться. Отсутствующий live-логин MUST NOT заменяться синтетическим логином.

#### Scenario: Своя и чужая команды
- **WHEN** включён репозиторий demo-orders
- **THEN** участники demo-orders получают его target/URL и свои настроенные логины,
  а demo-payments не получает конфигурацию demo-orders

#### Scenario: Повтор seed и ошибка настройки
- **WHEN** seed импортирован повторно или в env задан URL вместо owner/repo
- **THEN** валидная live-конфигурация не теряется от seed, а неверная отклоняется безопасно

### Requirement: GH-SOURCE-2 Персональные данные GitHub
Агент SHALL использовать target авторизованного каталога для GitHub-брифа и H1.
Персональный бриф MUST показывать изменения своих PR и запросы ревью пользователю,
ссылки MUST вести на полученные GitHub-объекты. H2-ссылка на GitHub MUST использовать
live URL каталога при его наличии. Внешние вызовы MUST оставаться read-only;
DEMO_MODE MUST продолжать использовать только старые фикстуры без сети.

#### Scenario: Персональный бриф проекта
- **WHEN** GitHub возвращает свои и чужие PR указанной репы
- **THEN** бриф содержит только релевантные пользователю изменения со ссылками на них

#### Scenario: Ссылка и отказ сервиса
- **WHEN** пользователь спрашивает где репозиторий или GitHub отвечает ошибкой
- **THEN** ссылка берётся из каталога, а ошибка источника не выдаётся за отсутствие доступа

### Requirement: GH-SOURCE-3 Совместимость живых ответов
H1 SHALL разбирать items/nextPage из GitHub MCP v2.1.0 и проходить до 10 страниц;
неполная/некорректная пагинация MUST давать unknown, а не missing. Live-сборщик SHALL
читать до 100 последних обновлённых PR, включая закрытые свои PR, отзывы и комментарии
обсуждения/кода. К старым фикстурам MUST NOT добавляться сетевые запросы. BackendData
SHALL переводить info ↔ information и calendar ↔ google_calendar на REST-границе.

#### Scenario: Вторая страница участников
- **WHEN** логин пользователя есть только на второй странице items
- **THEN** H1 возвращает granted, а ошибка следующей страницы даёт unknown

#### Scenario: Одобрение и хранение
- **WHEN** получено одобрение своего PR и информационный пункт сохраняется в backend
- **THEN** REST получает information и восстановленный пункт агента содержит info
