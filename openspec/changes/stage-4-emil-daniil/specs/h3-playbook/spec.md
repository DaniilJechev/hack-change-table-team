## MODIFIED Requirements

### Requirement: FR-H3-01 Индекс по снимку playbook
Скрипт индексации SHALL разбивать файлы снимка playbook на фиксированном коммите на фрагменты по заголовкам markdown и сохранять для каждого текст, файл, заголовок и URL на GitHub с якорем в файл индекса, который поставляется вместе с агентом. Для режимов поиска `vector` и `rrf` скрипт MUST дополнительно сохранять эмбеддинг каждого фрагмента в таблицу `rag_chunks` (pgvector).

#### Scenario: Индексация
- **WHEN** запускается `make ingest`
- **THEN** в индексе появляются фрагменты, у каждого заполнены файл, заголовок, URL и текст

#### Scenario: Повторная индексация
- **WHEN** индексация запускается повторно на том же коммите
- **THEN** число фрагментов не меняется, дублей не появляется

#### Scenario: Индексация с эмбеддингами
- **WHEN** `make ingest` запускается при `RAG_SEARCH_MODE=rrf`
- **THEN** в таблице `rag_chunks` столько же строк, сколько фрагментов в индексе, и у каждой есть эмбеддинг

### Requirement: FR-H3-03 Отказ при отсутствии ответа
Если лучшие фрагменты не покрывают вопрос — в вопросе есть слово, которого нет во всём playbook, либо близость лучшего фрагмента ниже порога режима, — бот SHALL отвечать «В playbook этого нет» и MUST показывать кнопку [Спросить наставника]. LLM MAY дополнительно отказаться, если найденные фрагменты не отвечают на вопрос.

#### Scenario: Вопрос вне корпуса
- **WHEN** стажёр спрашивает «Какой пароль от Wi-Fi в офисе?»
- **THEN** бот отвечает «В playbook этого нет» с кнопкой [Спросить наставника]

#### Scenario: Фрагменты не отвечают на вопрос
- **WHEN** LLM возвращает, что найденные фрагменты не содержат ответа
- **THEN** бот отвечает «В playbook этого нет» с кнопкой [Спросить наставника]

## ADDED Requirements

### Requirement: FR-H3-06 Режимы поиска
Режим поиска SHALL выбираться переменной окружения `RAG_SEARCH_MODE`: `bm25` (поиск по словам, значение по умолчанию), `vector` (эмбеддинги и pgvector) или `rrf` (объединение обоих списков по Reciprocal Rank Fusion). В режиме `bm25` модель эмбеддингов MUST NOT загружаться в память, а база данных MUST NOT использоваться. В режимах `vector` и `rrf` модель MUST загружаться лениво — при первом вопросе по playbook; при недоступности модели или базы поиск MUST продолжать работать в режиме `bm25`.

#### Scenario: Режим bm25
- **WHEN** задан `RAG_SEARCH_MODE=bm25` и стажёр задаёт вопрос по playbook
- **THEN** бот отвечает, а библиотеки эмбеддингов не импортируются

#### Scenario: Режим rrf
- **WHEN** задан `RAG_SEARCH_MODE=rrf`, эмбеддинги проиндексированы и стажёр спрашивает «Что такое Zero Bug Policy?»
- **THEN** лучший фрагмент — раздел о Zero Bug Policy из `development-principles.md`

#### Scenario: База недоступна
- **WHEN** задан `RAG_SEARCH_MODE=rrf`, а pgvector не отвечает
- **THEN** бот отвечает по поиску `bm25` и один раз пишет предупреждение в журнал
