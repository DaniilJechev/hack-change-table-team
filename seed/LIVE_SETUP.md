# Подготовка реальных тестовых объектов — передача Илье и команде

Статус: аккаунтов и серверов пока нет, Илья разрабатывает свою часть. По уточнению Даниила сейчас готовятся только код и фикстуры.
Ниже план ручной подготовки тестового окружения, не выполненные внешние действия. Все объекты учебные; не используйте реальные данные сотрудников Авито.

| Сервис | Что подготовить в отдельном тестовом пространстве | Что передать клиенту |
|---|---|---|
| GitHub | Репозиторий orders-onboarding, открытый PR по ORD-118, синтетическое изменение и ревью | owner/repo, PR number, точный MCP endpoint или команда stdio, PAT только чтения |
| Jira | Проект ORD, эпик ORD-100, задача ORD-118 и учебное назначение | URL объекта, issue key, адрес mcp-atlassian; аккаунт с просмотром |
| Calendar | Отдельный календарь, стендап 11 ноября, перенос 09:30 → 10:30, связь с ORD-118 | Calendar ID, Event ID, адрес MCP; доступ service account на чтение |
| Miro | Учебная доска, viewer-аккаунт, для второго шага ему выдаётся доступ вручную владельцем | Board/content item ID, OAuth команды, проверенный tools/list |
| Telegram | Отдельная учебная группа; пользователь добавляет бота и тестовых участников | Chat ID, привязки тестовых Telegram ID; для getChatMember бот — администратор |

Права выдаёт владелец тестового пространства. Агент не создаёт репозитории, PR, задачи, встречи, доски, чаты и не выдаёт доступы.
После подготовки замените not_created в отдельном живом manifest только на основании фактически созданных объектов. Синтетический seed/day_scenario.json остаётся независимым и воспроизводимым.

## Приёмка передачи
1. Илья передаёт адреса трёх MCP-серверов и выбранный способ GitHub stdio/HTTP; server-side read-only настройки подтверждены.
2. Учётные данные записаны в локальный .env, не в чат и не в Git.
3. Запускается discover --live. Имена и схемы сохраняются с origin=recorded только при реальном tools/list.
4. Проверяются четыре отдельных tools/call с аргументами реальных учебных объектов; результат отдельно от успеха discovery.
5. Выполняется разрешённая запись --live --record; фикстуры просматриваются на секреты и персональные данные до коммита.
6. Miro OAuth проверяется в реальном тестовом аккаунте; без этого нельзя объявлять интеграцию Miro завершённой.

Ссылки example.invalid в synthetic-наборе — явные демонстрационные адреса, они не выдают выдуманные объекты за настоящие и не отправляются пользователям как реальные источники.
