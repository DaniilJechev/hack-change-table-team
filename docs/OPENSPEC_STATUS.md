## Оставлено активным

| Изменение | Причина / следующий шаг |
|---|---|
| agent-orchestrator | Есть незакрытые пункты согласования, зависимость от stage-4-langgraph-memory и ручной LLM-прогон |
| stage-4-langgraph-memory | Есть незакрытые согласование/приёмка и LLM-eval; не закрывать по одному наличию кода |
| agent-turn-trace | Остался пункт согласования; изменяет agent-orchestrator, базовая спецификация которого ещё не создана |
| single-executor-node | Осталась ручная проверка Studio; зависит от agent-orchestrator |
| live-run-fixes | Открыты ручные сценарии и пункты evals; Telegram-format/context-memory связаны с другими дельтами |
| telegram-citations | Требуется ручной Telegram-прогон и архивирование после live-run-fixes |
| evaluator-quality | Не закончены полные H0/H1/H4, независимые вопросы, повторы и калибровка судьи |
| windows-desktop-client | Не закрыта ручная приёмка установленного Windows-клиента |
| desktop-github-releases | Checklist закрыт; отдельную сверку release-workflow/публикации в этой работе не проводили, архивирование отложено |

Общий `openspec validate --all` проверяет форму дельт, но не заменяет ручную приёмку
и не гарантирует, что любую комбинацию MODIFIED-дельт можно сразу архивировать.
Сообщения CLI о несуществующих base `context-memory`/`telegram-format` требуют
порядка применения зависимостей, а не удаления дельт или принудительного закрытия.

## Новые метрики

[METRICS.md](METRICS.md) — согласованный каталог и план, не реализованная телеметрия.
Перед кодом OUT-01…06 нужна отдельная дельта: схема событий, problem_id, идемпотентность,
права, demo/live и сценарии знаменателей/неизвестного исхода. Этот аудит не добавляет
такие требования в активные спецификации как уже выполненные.
