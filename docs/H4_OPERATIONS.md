# H4: запуск и ручная проверка

Спецификация: [h4-equator](../openspec/specs/h4-equator/spec.md). Учебная структура синтетическая,
не регламент Авито. Проверяется извлекаемый текст PDF/PPTX, файл не редактируется.
Картинки разрешены, OCR и визуальная оценка не выполняются.

## Настройки

| Переменная | По умолчанию | Назначение |
|---|---|---|
| H4_RECOMMENDED_MAX_SLIDES | 10 | Рекомендательное число слайдов |
| H4_RECOMMENDED_MAX_WORDS_PER_SLIDE | 100 | Рекомендательное число слов на слайде |
| H4_HISTORY_TTL_DAYS | 7 | Срок истории в днях с создания проверки |
| H4_HISTORY_PATH | пусто вне Compose | Файл SQLite истории демо; Compose использует /h4/history.sqlite |

Числовые параметры — положительные целые; срок истории ограничен 36500 днями в агенте и backend.
Превышение рекомендательных порогов не блокирует
отправку. Технические ограничения отдельные: 10 МиБ и 30 слайдов. После изменения env
пересоздайте соответствующий контейнер; срок задавайте одинаковым для backend и agent.

Живая история хранится в PostgreSQL через REST backend. История демо — локально в томе
`h4_history`, без HTTP к backend. Без H4_HISTORY_PATH вне Compose используется память,
которая не переживает перезапуск. Исходные файлы не входят в историю; для отправки
сохраняется Telegram file_id. Не удаляйте тома, если история нужна.

## Проверка в Telegram

1. Включите `/demo`. Отправьте `fixtures/equator/bad.pdf`: ожидаются замечания без отправки.
2. Отправьте `fixtures/equator/good.pdf`: ожидаются обязательные проверки и рекомендации.
3. Сравните отчёты: исправленные, оставшиеся и новые замечания должны быть перечислены.
4. Нажмите «Отправить наставнику». В демо копия файла и отчёт показываются в том же чате;
   это не проверка доставки реальному наставнику.
5. Повторите нажатие: подтверждённо доставленные части не должны дублироваться.
6. После новой плохой версии старая кнопка не должна отправлять прежний файл.
7. Проверьте `/brief` и «Ещё N»: одинаковые номера/источники/стиль и ссылки у каждого пункта.
8. Для собственного PPTX нужен локальный PowerPoint-MCP; без него используйте PDF.

`/reset` очищает диалог, сохраняя историю H4. `/demo reset` очищает свою историю демо.
Отметка трекера означает проверку AI-buddy, а доставка имеет собственный статус.

## Проверки разработчика

- Python: `uv run --project agent --extra dev pytest agent/tests --cov=buddy`.
- Backend с изолированной PostgreSQL: `python infra/test_backend.py` (нужны Docker и Go).
- OpenSpec: `openspec validate --all`.
- Рекомендации без LLM: `PYTHONPATH=agent uv run --project agent python evals/run_h4.py`.
- Синтетический прогон настоящей модели: та же команда с `--live` и настроенной `.env`.
  Проверяйте качество замечаний вручную; прохождение JSON-схемы не означает полезность.

Для живой приёмки нужны реальные Jira-данные, привязанные стажёр и наставник одной команды.
Сбой источника не считается отсутствующей задачей. Проверка собственных картинок требует
текстового описания обязательных сведений. Запуск бота выполняется только по поручению пользователя.
